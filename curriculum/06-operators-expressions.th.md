# บทที่ 6: Operators, Expressions, Statements

## แนวคิดหลัก (Concept)

เมื่อมีตัวแปรและชนิดข้อมูลแล้ว (บทที่ 5) ขั้นต่อไปคือการนำค่าเหล่านั้นมา**คำนวณและสร้างเป็นคำสั่งที่โปรแกรมทำงานตาม** สามแนวคิดหลักที่ประกอบกันเป็นทุกบรรทัดของโค้ด:

- **Operator (ตัวดำเนินการ)** — สัญลักษณ์ที่ใช้ทำ operation กับค่าหนึ่งหรือหลายค่า เช่น `+`, `-`, `==`, `and` แบ่งเป็นกลุ่มหลักๆ: arithmetic (คำนวณ), comparison (เปรียบเทียบ), logical (ตรรกะ), assignment (กำหนดค่า), bitwise (ระดับบิต)
- **Expression (นิพจน์)** — ส่วนของโค้ดที่**ประเมินแล้วได้ค่าออกมา** เช่น `3 + 4` (ได้ 7), `age > 18` (ได้ True/False), `name` (ได้ค่าของตัวแปร)
- **Statement (คำสั่ง)** — บรรทัดโค้ดที่**สั่งให้โปรแกรมทำอะไรบางอย่าง** อาจมี expression อยู่ข้างในหรือไม่ก็ได้ เช่น `x = 3 + 4` (assignment statement), `if age > 18:` (control statement), `print(x)` (function call statement)

ความสัมพันธ์: **Expression ให้ค่า → Statement ใช้ค่านั้นทำสิ่งใดสิ่งหนึ่ง** ทุกโปรแกรมคือลำดับของ statement ที่ประกอบด้วย expression ซ้อนกันอยู่ข้างใน

## ทำไมต้องมีสิ่งนี้ (Why it exists)

- **Operator มีไว้เป็น "คำกริยา" ของภาษาโปรแกรม**: เช่นเดียวกับที่ภาษามนุษย์ต้องมีคำกริยาถึงจะสื่อสารการกระทำได้ ภาษาโปรแกรมต้องมี operator ถึงจะทำให้ข้อมูล (ตัวแปร/ค่า) มีปฏิสัมพันธ์กันได้ ไม่ใช่แค่นอนอยู่เฉยๆ
- **Expression vs Statement มีไว้แยกแยะ "สิ่งที่ให้ค่า" ออกจาก "สิ่งที่สั่งงาน"**: การแยกสองแนวคิดนี้ชัดเจนช่วยให้เข้าใจว่าทำไมบางอย่างเขียนซ้อนกันได้ (`print(3 + 4)` — expression `3+4` ซ้อนอยู่ใน statement `print(...)`) แต่บางอย่างซ้อนกันไม่ได้ (นำ `if` statement ไปเป็นส่วนหนึ่งของ expression ตรงๆ ไม่ได้ในหลายภาษา)
- **Operator precedence (ลำดับความสำคัญ) มีไว้ให้ผลลัพธ์คาดเดาได้แน่นอน**: ถ้าไม่มีกฎตายตัวว่า `*` ทำก่อน `+` เสมอ นิพจน์เดียวกันอาจให้ผลลัพธ์ต่างกันในแต่ละครั้งที่รัน ซึ่งเป็นหายนะสำหรับการเขียนโปรแกรม

## เปรียบเทียบกับชีวิตจริง (Real-world analogy)

- **Operator** เหมือน **เครื่องหมายในสูตรอาหาร** — "ผสม", "ต้ม", "หั่น" คือคำกริยาที่บอกว่าต้องทำอะไรกับวัตถุดิบ (ตัวแปร) เพื่อให้ได้ผลลัพธ์ใหม่
- **Expression** เหมือน **สูตรคำนวณในเครื่องคิดเลข** — พิมพ์ `3 × 4 + 2` แล้วกด `=` จะได้ค่าออกมาเป็น `14` เสมอ ไม่ว่าจะกดกี่ครั้งก็ได้ผลเดิม (ถ้าค่าตัวแปรไม่เปลี่ยน)
- **Statement** เหมือน **ประโยคคำสั่งในสูตรอาหารทั้งประโยค** — "ใส่ไข่ 2 ฟองที่ตีแล้วลงในกระทะ" ทั้งประโยคคือคำสั่ง (statement) ส่วน "ไข่ 2 ฟองที่ตีแล้ว" คือผลลัพธ์จากขั้นตอนก่อนหน้า (expression) ที่ถูกนำมาใช้ในคำสั่งนี้

## แผนภาพอธิบาย (Visual explanation)

### ประเภทของ Operator

```
Arithmetic (คำนวณ)     +   -   *   /   %   **
Comparison (เปรียบเทียบ) ==  !=  >   <   >=  <=
Logical (ตรรกะ)         and  or  not   (หรือ &&  ||  !  ในบางภาษา)
Assignment (กำหนดค่า)   =   +=  -=  *=  /=
Bitwise (ระดับบิต)      &   |   ^   ~   <<  >>
```

### ลำดับความสำคัญ (Operator Precedence) — ตัวอย่าง

```
นิพจน์:  3 + 4 * 2

ผิด (บวกก่อนคูณ):   (3 + 4) * 2 = 14   ✗
ถูก (คูณก่อนบวก):   3 + (4 * 2) = 11   ✓  ← เพราะ * มีความสำคัญสูงกว่า +

ลำดับความสำคัญทั่วไป (จากสูงไปต่ำ):
  1. วงเล็บ ()
  2. ยกกำลัง **
  3. คูณ/หาร/มอด  *  /  %
  4. บวก/ลบ  +  -
  5. เปรียบเทียบ  <  >  ==  !=
  6. ตรรกะ  and / or
```

### Expression vs Statement

```
x = 3 + 4
│    └──┬──┘
│       └── Expression (ให้ค่า 7)
└── ทั้งบรรทัดคือ Statement (คำสั่ง "กำหนดค่า")

print(3 + 4)
      └──┬──┘
         └── Expression (ให้ค่า 7) ซ้อนอยู่ใน...
└──────────── Statement (คำสั่ง "เรียกฟังก์ชัน print")

if age > 18:      ← "age > 18" เป็น Expression (ให้ค่า True/False)
    print("ok")   ← ทั้ง "if...:" เป็น Statement (คำสั่งควบคุมทิศทาง)
```

## ตัวอย่างโค้ด (Code example)

```python
# ===== Arithmetic Operators =====
a, b = 10, 3
print(a + b)    # 13
print(a - b)    # 7
print(a * b)    # 30
print(a / b)    # 3.333... (float division)
print(a // b)   # 3        (integer/floor division)
print(a % b)    # 1        (modulo, เศษจากการหาร)
print(a ** b)   # 1000     (ยกกำลัง)

# ===== Comparison & Logical Operators =====
age = 20
is_adult = age >= 18          # Expression -> True
has_id = True
can_enter = is_adult and has_id   # Expression -> True

# ===== Operator Precedence ในทางปฏิบัติ =====
result = 3 + 4 * 2      # 11, ไม่ใช่ 14 (คูณก่อนบวก)
result2 = (3 + 4) * 2   # 14, วงเล็บบังคับลำดับใหม่

# ===== Assignment Operators (ลัด) =====
score = 10
score += 5   # เทียบเท่า score = score + 5  -> 15
score *= 2   # เทียบเท่า score = score * 2  -> 30
```

## ทำงานทีละขั้นตอน (Step-by-step execution)

1. `a / b` เมื่อ `a=10, b=3` — Python ประเมิน expression นี้โดยทำ **true division** ได้ผลลัพธ์เป็น float `3.333...` ต่างจาก `a // b` ที่ทำ **floor division** ปัดเศษทศนิยมทิ้งเหลือ `3` (int)
2. `result = 3 + 4 * 2` — ตัว interpreter/compiler จะดู **operator precedence** ก่อนว่า `*` มีความสำคัญสูงกว่า `+` จึงคำนวณ `4 * 2 = 8` ก่อน แล้วค่อยบวก `3 + 8 = 11` ผลลัพธ์ถูกเก็บใน `result` ผ่าน assignment
3. `can_enter = is_adult and has_id` — Python ประเมิน `is_adult` (True) และ `has_id` (True) ก่อน แล้วนำมาผ่าน operator `and` ซึ่งคืนค่า True ก็ต่อเมื่อทั้งสองฝั่งเป็น True เท่านั้น (short-circuit evaluation: ถ้าฝั่งซ้ายเป็น False ภาษาส่วนใหญ่จะไม่ประเมินฝั่งขวาเลย เพื่อประหยัดเวลา)
4. `score += 5` — เป็น **compound assignment operator** ทำงานเทียบเท่ากับ `score = score + 5` แต่เขียนสั้นกว่าและในหลายภาษามีประสิทธิภาพดีกว่าเล็กน้อย (ไม่ต้องประเมินตัวแปรฝั่งซ้ายซ้ำสองครั้ง)

## Time Complexity

Operator พื้นฐาน (arithmetic, comparison, logical) บนชนิดข้อมูลพื้นฐาน (int, float, bool) ทำงานเป็น **O(1)** เสมอ เพราะเป็นคำสั่งระดับ CPU โดยตรง (ตามที่เรียนใน fetch-decode-execute cycle บทที่ 1) แต่ operator บนโครงสร้างข้อมูลขนาดใหญ่ (เช่น เปรียบเทียบ string ยาว หรือ `+` ระหว่าง list สองอัน) อาจมีความซับซ้อนสูงกว่านั้น เช่น O(n) ตามขนาดข้อมูล

## Space Complexity

Expression ที่ประเมินค่าพื้นฐาน (int, float, bool) ใช้พื้นที่คงที่ O(1) แต่ expression ที่สร้างโครงสร้างข้อมูลใหม่ (เช่น การรวม string หรือ list ด้วย `+`) จะใช้พื้นที่เพิ่มตามขนาดผลลัพธ์ O(n)

## แนวทางปฏิบัติที่ดี (Best Practices)

- ใช้วงเล็บเพื่อความชัดเจน แม้ operator precedence จะให้ผลลัพธ์ถูกต้องอยู่แล้ว เพราะช่วยให้คนอ่านโค้ดไม่ต้องท่องจำลำดับความสำคัญ (`(3 + 4) * 2` อ่านง่ายกว่าการพึ่งพา precedence ล้วนๆ ในนิพจน์ซับซ้อน)
- ใช้ compound assignment (`+=`, `-=`) เมื่อเหมาะสม เพื่อความกระชับและลดโอกาสพิมพ์ชื่อตัวแปรผิดฝั่งใดฝั่งหนึ่ง
- ระวังการใช้ `/` กับจำนวนเต็มในบางภาษา (เช่น Python 2 หรือ Java) ที่อาจให้ผลเป็น integer division โดยไม่รู้ตัว ทำให้เศษทศนิยมหายไป
- ใช้ short-circuit evaluation ให้เป็นประโยชน์ เช่น `if obj is not None and obj.value > 0:` — เช็ค `None` ก่อนเสมอเพื่อป้องกัน error จากการเข้าถึง attribute ของ `None`

## ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

- สับสน `=` (assignment) กับ `==` (comparison) — เขียน `if x = 5:` แทนที่จะเป็น `if x == 5:` (ในบางภาษาจะ error ทันที แต่บางภาษาเช่น C ยอมให้ compile ผ่านแล้วเกิดบั๊กเงียบๆ)
- ลืมลำดับความสำคัญของ operator แล้วคาดหวังผลลัพธ์ผิด เช่น คิดว่า `not a == b` จะได้ผลเหมือน `not (a == b)` เสมอ ทั้งที่บางภาษาตีความต่างกันถ้าไม่ระวัง
- ใช้ integer division (`//` หรือ `/` ในบางภาษา) โดยไม่ตั้งใจ แล้วสงสัยว่าทำไมผลลัพธ์ทศนิยมหายไป
- เข้าใจผิดว่า `and`/`or` คืนค่า True/False เสมอ — ในหลายภาษา (Python, JavaScript) `and`/`or` คืน**ค่าจริงของ operand หนึ่งฝั่ง** ไม่ใช่แค่ boolean เสมอไป (เช่น `0 or "default"` ได้ `"default"`)

## ข้อคิดสำคัญ (Key Takeaways)

- Operator คือสัญลักษณ์ที่ทำ operation กับค่า แบ่งเป็น arithmetic, comparison, logical, assignment, bitwise
- Expression คือส่วนของโค้ดที่ประเมินแล้วได้ค่าออกมา ส่วน Statement คือคำสั่งที่สั่งให้โปรแกรมทำสิ่งใดสิ่งหนึ่ง (ซึ่งอาจมี expression ซ้อนอยู่ข้างใน)
- Operator precedence กำหนดลำดับการคำนวณที่แน่นอน ใช้วงเล็บช่วยความชัดเจนเสมอเมื่อไม่แน่ใจ
- Short-circuit evaluation ของ `and`/`or` ช่วยทั้งประสิทธิภาพและป้องกัน error จากการประเมินฝั่งขวาที่ไม่จำเป็น
- ความเข้าใจเรื่องนี้เป็นพื้นฐานก่อนเข้าสู่บทถัดไป: Input/Output และ Type Conversion ซึ่งต้องใช้ operator และ expression ร่วมกันตลอด
