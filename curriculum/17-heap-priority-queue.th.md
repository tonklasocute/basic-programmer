# บทที่ 17: Heap & Priority Queue

## แนวคิดหลัก (Concept)

> **ข้อควรระวังเรื่องชื่อ**: คำว่า "Heap" ในบทนี้เป็นคนละเรื่องกับ "Heap" (หน่วยความจำ) ที่เรียนในบทที่ 3 โดยสิ้นเชิง! บทที่ 3 พูดถึง**โซนหน่วยความจำ**ที่เก็บ object แบบไดนามิก ส่วนบทนี้พูดถึง**โครงสร้างข้อมูลชนิดหนึ่ง**ที่บังเอิญใช้ชื่อเดียวกัน (เป็นความบังเอิญทางประวัติศาสตร์ของวงการ CS ที่ทำให้มือใหม่สับสนบ่อยมาก)

จากบทที่ 16 BST ตอบโจทย์ "ค้นหาค่าใดก็ได้" ได้ดี แต่ถ้าโจทย์แคบลงเหลือแค่ **"หาค่ามากที่สุด/น้อยที่สุดให้เร็วที่สุดตลอดเวลา"** จะมีโครงสร้างข้อมูลที่เฉพาะทางและมีประสิทธิภาพกว่า — นั่นคือ **Heap**

- **Heap (ฮีป — โครงสร้างข้อมูล)** — Binary Tree พิเศษที่มีกฎ: **ทุก Node ต้องมีค่ามากกว่า(หรือน้อยกว่า)ลูกของมันเสมอ** และต้นไม้ต้อง **สมบูรณ์เกือบทั้งหมด (complete tree)** คือเติมข้อมูลจากซ้ายไปขวาทีละชั้น ไม่มีช่องว่าง
  - **Max-Heap** — Node แม่มีค่า**มากกว่า**ลูกเสมอ (ค่าสูงสุดอยู่ที่ root เสมอ)
  - **Min-Heap** — Node แม่มีค่า**น้อยกว่า**ลูกเสมอ (ค่าต่ำสุดอยู่ที่ root เสมอ)
- **Priority Queue (คิวลำดับความสำคัญ)** — โครงสร้างข้อมูลเชิงนามธรรม (abstract) ที่หยิบ "สิ่งที่มีความสำคัญที่สุด" ออกมาก่อนเสมอ (ไม่ใช่ตามลำดับเข้า-ออกแบบ Queue ธรรมดาในบทที่ 14) — **Heap คือวิธี implement Priority Queue ที่นิยมที่สุด**

## ทำไมต้องมีสิ่งนี้ (Why it exists)

- **Heap มีไว้ตอบโจทย์ "หา max/min เร็วที่สุด" โดยเฉพาะ**: BST ก็หา max/min ได้ (O(log n)) แต่ Heap ทำสิ่งนี้ได้เร็วกว่า คือ **O(1)** เพราะค่าที่มากสุด/น้อยสุดอยู่ที่ root เสมอตามกฎของมัน — แลกมาด้วยการที่ Heap **ไม่รองรับการค้นหาค่าอื่นๆ ที่ไม่ใช่ max/min ได้เร็วเหมือน BST** (Heap ไม่มีกฎ "ซ้ายน้อยกว่าขวา" แบบ BST เลย)
- **Priority Queue มีไว้จำลองสถานการณ์จริงที่ "ความสำคัญ" สำคัญกว่า "ลำดับเวลาที่มาถึง"**: ในโรงพยาบาลฉุกเฉิน คนไข้อาการหนักต้องได้รับการรักษาก่อนคนที่มาก่อนแต่อาการเบากว่า — Queue ธรรมดา (FIFO จากบทที่ 14) ทำสิ่งนี้ไม่ได้ ต้องใช้ Priority Queue แทน
- **การเป็น "complete tree" มีไว้ให้ Heap เก็บด้วย Array ได้อย่างมีประสิทธิภาพ**: เพราะโครงสร้างเติมเต็มจากซ้ายไปขวาเสมอไม่มีช่องว่าง จึงสามารถคำนวณตำแหน่ง parent/child ด้วยสูตรคณิตศาสตร์บน index ของ array ได้เลย ไม่ต้องใช้ pointer เหมือน Tree ทั่วไปในบทที่แล้ว (ประหยัดหน่วยความจำกว่า)

## เปรียบเทียบกับชีวิตจริง (Real-world analogy)

- **Max-Heap** เหมือน **การแข่งขันบาสเก็ตบอลแบบแพ้คัดออก (single elimination)** — ผู้ชนะในแต่ละคู่ (Node) จะสูงกว่า/เก่งกว่าคู่แข่งที่แพ้ (ลูก) เสมอ แต่ไม่ได้บอกว่าทีมอันดับ 5 กับอันดับ 6 ใครเก่งกว่ากัน (ต่างจาก BST ที่จัดลำดับทุกตัวชัดเจน)
- **Priority Queue** เหมือน **ห้องฉุกเฉินโรงพยาบาล (Emergency Room Triage)** — คนไข้ถูกเรียกตามความรุนแรงของอาการ (priority) ไม่ใช่ตามลำดับที่มาถึงประตู แม้จะมาทีหลังแต่ถ้าอาการหนักกว่าก็ได้รับการรักษาก่อน

## แผนภาพอธิบาย (Visual explanation)

### Max-Heap — โครงสร้างและกฎ

```
                    ┌─────┐
                    │ 90  │  ← Root: ค่ามากสุดเสมอ
                    └──┬──┘
              ┌────────┴────────┐
           ┌──┴──┐            ┌──┴──┐
           │ 70  │            │ 80  │  ← ทั้งคู่ < 90 (พ่อ)
           └──┬──┘            └─────┘
        ┌──────┴──────┐
     ┌──┴──┐        ┌──┴──┐
     │ 40  │        │ 60  │  ← ทั้งคู่ < 70 (พ่อ)
     └─────┘        └─────┘

สังเกต: 80 > 60 ก็ได้ (ไม่มีกฎเทียบข้ามสาขา!) ต่างจาก BST ที่ต้องเทียบทั้งต้น
กฎ Heap สนใจแค่ "พ่อ vs ลูกโดยตรง" เท่านั้น ไม่ใช่ "ทุก Node ในต้นไม้ทั้งหมด"
```

### การเก็บ Heap ด้วย Array (ไม่ใช้ pointer!)

```
Array:     [90, 70, 80, 40, 60]
Index:       0   1   2   3   4

สูตรคำนวณตำแหน่งพ่อ-ลูกจาก index (i):
  parent(i)      = (i - 1) // 2
  left_child(i)  = 2*i + 1
  right_child(i) = 2*i + 2

ตรวจสอบ: index 1 (ค่า 70) มี left_child = 2*1+1 = 3 (ค่า 40) ✓ ตรงกับภาพต้นไม้ด้านบน
         index 1 (ค่า 70) มี parent = (1-1)//2 = 0 (ค่า 90) ✓ ถูกต้อง
```

### การแทรกค่าใหม่ (Insert) — "ลอยขึ้น" (Sift Up / Bubble Up)

```
Max-Heap เดิม:  [90, 70, 80, 40, 60]

แทรก 95 เข้าไปท้าย array ก่อน:  [90, 70, 80, 40, 60, 95]

เทียบ 95 กับ parent (70) -> 95 > 70 -> สลับตำแหน่ง!
[90, 95, 80, 40, 60, 70]

เทียบ 95 กับ parent ใหม่ (90) -> 95 > 90 -> สลับอีก!
[95, 90, 80, 40, 60, 70]

95 ถึง root แล้ว หยุด -> Max-Heap สมบูรณ์ (95 เป็นค่าสูงสุดอยู่ root)
```

### การหยิบค่าสูงสุดออก (Extract-Max) — "จมลง" (Sift Down / Bubble Down)

```
Max-Heap:  [95, 90, 80, 40, 60, 70]

1. หยิบ root (95) ออกไปใช้งาน
2. เอาตัวสุดท้าย (70) มาไว้ที่ root แทนชั่วคราว: [70, 90, 80, 40, 60]
3. เทียบ 70 กับลูกทั้งสอง (90, 80) -> เลือกตัวที่มากกว่า (90) มาสลับ:
   [90, 70, 80, 40, 60]
4. เทียบ 70 กับลูกของมัน (40) -> 70 > 40 อยู่แล้ว หยุด

ผลลัพธ์: [90, 70, 80, 40, 60] -> root ใหม่คือ 90 (ค่าสูงสุดถัดไป) ถูกต้อง!
```

## ตัวอย่างโค้ด (Code example)

```python
import heapq   # Python มี Min-Heap สำเร็จรูปในตัว

# ===== Min-Heap พื้นฐาน (heapq เป็น Min-Heap เสมอ) =====
min_heap = []
heapq.heappush(min_heap, 50)
heapq.heappush(min_heap, 30)
heapq.heappush(min_heap, 70)
heapq.heappush(min_heap, 10)

print(min_heap[0])              # 10 -> ค่าน้อยสุดอยู่ index 0 เสมอ, เข้าถึง O(1)
print(heapq.heappop(min_heap))  # 10 -> หยิบค่าน้อยสุดออก, จัดโครงสร้างใหม่ O(log n)
print(heapq.heappop(min_heap))  # 30

# ===== ทำ Max-Heap โดยการใส่ค่าติดลบ (เทคนิคยอดนิยม) =====
max_heap = []
for value in [50, 30, 70, 10]:
    heapq.heappush(max_heap, -value)     # เก็บค่าติดลบ -> น้อยสุดของค่าติดลบ = มากสุดของค่าจริง
print(-max_heap[0])                       # 70 -> ค่ามากสุดจริง

# ===== Priority Queue: ระบบคิวห้องฉุกเฉิน =====
er_queue = []
heapq.heappush(er_queue, (1, "กระดูกหัก"))       # (priority, ชื่ออาการ) - เลขน้อย = ด่วนกว่า
heapq.heappush(er_queue, (3, "ไข้หวัด"))
heapq.heappush(er_queue, (0, "หัวใจหยุดเต้น"))    # ด่วนที่สุด (priority=0)

while er_queue:
    priority, condition = heapq.heappop(er_queue)
    print(f"เรียกรักษา: {condition} (priority={priority})")
# ผลลัพธ์: หัวใจหยุดเต้น -> กระดูกหัก -> ไข้หวัด (ไม่ใช่ตามลำดับที่ push เข้าไป!)
```

## ทำงานทีละขั้นตอน (Step-by-step execution)

1. `heapq.heappush(min_heap, 10)` — ค่า `10` ถูกใส่ต่อท้าย array ภายในก่อน แล้ว `heapq` ทำ **sift up** เทียบ `10` กับ parent ของมันซ้ำๆ สลับตำแหน่งขึ้นไปเรื่อยๆ จนกว่าจะเจอ parent ที่น้อยกว่าหรือถึง root — สุดท้าย `10` ซึ่งเป็นค่าน้อยที่สุด ลอยขึ้นไปอยู่ที่ index 0 (root) พอดี
2. `heapq.heappop(min_heap)` — หยิบค่าที่ index 0 (root, ค่าน้อยสุด) ออกไปเก็บไว้ก่อน แล้วเอาสมาชิกตัวสุดท้ายของ array มาไว้ที่ index 0 แทนชั่วคราว จากนั้นทำ **sift down** เทียบกับลูกทั้งสองฝั่ง สลับกับตัวที่น้อยกว่าไปเรื่อยๆ จนกว่าจะอยู่ในตำแหน่งที่ถูกต้องตามกฎ Heap — นี่คือเหตุผลที่ extract เป็น **O(log n)** ไม่ใช่ O(1) (แม้ว่าการ "ดู" ค่า root จะเป็น O(1) ก็ตาม)
3. `er_queue` ตัวอย่าง — Python เปรียบเทียบ tuple `(priority, condition)` โดยดูค่าตัวแรกก่อน (`priority`) ทำให้ tuple ที่มี priority น้อยกว่าลอยขึ้นไปอยู่ root เสมอ ผลลัพธ์คือ `heappop()` จะคืนอาการที่ด่วนที่สุด (`priority=0`) ออกมาก่อนเสมอ ไม่ว่าจะ push เข้าไปตามลำดับใดก็ตาม — นี่คือหัวใจของ Priority Queue ที่ต่างจาก Queue ธรรมดา (FIFO) ในบทที่ 14 โดยสิ้นเชิง

## Time Complexity

| Operation | Complexity | เหตุผล |
|---|---|---|
| ดูค่า max/min (peek) | O(1) | อยู่ที่ root/index 0 เสมอ |
| แทรกค่าใหม่ (push) | O(log n) | sift up สูงสุดตามความสูงของต้นไม้ |
| หยิบค่า max/min ออก (pop) | O(log n) | sift down สูงสุดตามความสูงของต้นไม้ |
| ค้นหาค่าอื่นที่ไม่ใช่ max/min | O(n) | ไม่มีกฎช่วยตัดข้อมูลทิ้งเหมือน BST — ต้องไล่ตรวจทีละตัว |

เหตุผลที่ push/pop เป็น O(log n): เพราะ Heap เป็น **complete tree** เสมอ (ไม่มีทางเอียงเหมือน BST ธรรมดาในบทที่แล้ว) ความสูงของมันจึงเป็น log(n) เสมอโดยไม่มีเงื่อนไข ต่างจาก BST ที่ต้องพึ่ง AVL ถึงจะรับประกันสิ่งนี้ได้

## Space Complexity

Heap ใช้พื้นที่ **O(n)** เก็บด้วย Array ตัวเดียว (ตามที่อธิบายด้านบน) — **ประหยัดหน่วยความจำกว่า BST/AVL** เพราะไม่ต้องเก็บ pointer ซ้าย-ขวาแยกต่างหากในแต่ละ Node (Tree ทั่วไปต้องมี `left`, `right` pointer ตามบทที่ 16 แต่ Heap ใช้แค่สูตรคำนวณ index)

## ข้อดี (Advantages)

- หา/หยิบค่า max หรือ min ได้เร็วมาก O(1) สำหรับ peek, O(log n) สำหรับ pop
- ใช้หน่วยความจำมีประสิทธิภาพกว่า Tree ทั่วไป เพราะเก็บด้วย Array แทน pointer
- รับประกันความสมดุล (complete tree) เสมอโดยไม่ต้องมีกลไก rebalance ซับซ้อนแบบ AVL

## ข้อเสีย (Disadvantages)

- ค้นหาค่าอื่นที่ไม่ใช่ max/min ช้า O(n) — ไม่เหมาะถ้าต้องการค้นหาค่าทั่วไป (ควรใช้ BST หรือ Hash Table แทน)
- ไม่รักษาลำดับการเรียงของข้อมูลทั้งหมด (รู้แค่ตัวที่มากสุด/น้อยสุด ไม่รู้ว่าตัวที่เหลือเรียงอย่างไร)

## การใช้งานจริง (Real-world usage)

- **Priority Queue** ในระบบ scheduling ของ operating system (จะเรียนในบท OS) — เลือกโปรเซสที่ควรได้ CPU ก่อนตาม priority
- อัลกอริทึม **Dijkstra's Shortest Path** และ **Prim's Minimum Spanning Tree** ใช้ Min-Heap เป็นแกนหลัก
- **Heap Sort** — อัลกอริทึมการเรียงลำดับที่ใช้หลักการ Heap (จะเรียนในบท Sorting)
- ระบบแจ้งเตือนที่ต้องประมวลผลเหตุการณ์ตามความสำคัญ/เวลาที่ใกล้ที่สุดก่อน (เช่น task scheduler, event simulation)
- หาค่า "Top K" ที่มากที่สุด/น้อยที่สุดจากข้อมูลจำนวนมาก โดยไม่ต้องเรียงข้อมูลทั้งหมด

## แนวทางปฏิบัติที่ดี (Best Practices)

- ใช้ Heap เมื่อโจทย์ต้องการแค่ "ค่ามากสุด/น้อยสุด" ซ้ำๆ ไม่ใช่ต้องการค้นหาค่าทั่วไป (ถ้าต้องการค้นหาค่าทั่วไปด้วย ให้กลับไปใช้ BST/Hash Table)
- ใน Python ที่มีแค่ Min-Heap สำเร็จรูป (`heapq`) ให้ใช้เทคนิคใส่ค่าติดลบเพื่อจำลอง Max-Heap แทนการเขียน Max-Heap เองใหม่ทั้งหมด
- เมื่อต้องเรียง priority หลายเงื่อนไข (เช่น priority เท่ากันให้เรียงตามเวลาที่มาถึง) ใช้ tuple ที่มีหลายค่า เพราะ Python เปรียบเทียบ tuple ทีละตำแหน่งตามลำดับให้อัตโนมัติ

## ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

- เข้าใจผิดว่า Heap เป็น BST หรือคาดหวังว่าข้อมูลทั้งหมดใน Heap จะเรียงลำดับ (Heap รับประกันแค่ parent-child เทียบกัน ไม่ได้เรียงลำดับทั้งต้น)
- พยายามค้นหาค่าที่ไม่ใช่ max/min ใน Heap แล้วคาดหวังความเร็วแบบ BST (จริงๆ เป็น O(n) เพราะไม่มีกฎช่วยตัดข้อมูล)
- สับสนระหว่าง Heap (โครงสร้างข้อมูล ในบทนี้) กับ Heap (หน่วยความจำ ในบทที่ 3) — เป็นคนละเรื่องกันโดยสิ้นเชิงแม้ชื่อเหมือนกัน
- ลืมว่า `heapq` ใน Python เป็น Min-Heap เสมอ แล้วพยายามใช้ตรงๆ เพื่อหาค่ามากสุดโดยไม่ใส่ค่าติดลบก่อน ทำให้ได้ผลลัพธ์ผิด

## ข้อคิดสำคัญ (Key Takeaways)

- Heap เป็น Binary Tree พิเศษที่มีกฎ parent-child (Max-Heap หรือ Min-Heap) และเป็น complete tree เสมอ ทำให้เก็บด้วย Array ได้อย่างมีประสิทธิภาพ
- Heap ตอบโจทย์ "หา max/min เร็วที่สุด" (O(1) peek, O(log n) pop) ได้ดีกว่า BST แต่ค้นหาค่าอื่นช้ากว่า (O(n))
- Priority Queue คือแนวคิดเชิงนามธรรมของ "หยิบสิ่งสำคัญที่สุดก่อน" ซึ่ง Heap เป็นวิธี implement ที่นิยมที่สุด ต่างจาก Queue ธรรมดา (FIFO) ในบทที่ 14 โดยสิ้นเชิง
- คำว่า "Heap" ในบทนี้ (โครงสร้างข้อมูล) กับในบทที่ 3 (หน่วยความจำ) เป็นคนละเรื่องกัน ต้องแยกให้ออกจากบริบท
- Heap เป็นแกนสำคัญของอัลกอริทึมที่จะเรียนภายหลัง เช่น Heap Sort, Dijkstra's Algorithm
- บทถัดไปจะเรียน Trie ซึ่งเป็นโครงสร้างข้อมูลต้นไม้อีกแบบที่ออกแบบมาเฉพาะสำหรับจัดการข้อมูลประเภทข้อความ/string
