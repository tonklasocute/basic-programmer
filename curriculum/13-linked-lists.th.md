# บทที่ 13: Linked Lists

## แนวคิดหลัก (Concept)

จากบทที่แล้วเรารู้ว่า Array มีจุดอ่อนสำคัญ: การแทรก/ลบสมาชิกที่ต้นหรือกลางต้อง "เลื่อน" สมาชิกทั้งหมด (O(n)) เพราะข้อมูลถูกบังคับให้อยู่ติดกันในหน่วยความจำ **Linked List (ลิงก์ลิสต์)** คือโครงสร้างข้อมูลที่แก้ปัญหานี้ โดยเปลี่ยนวิธีคิดใหม่ทั้งหมด

- **Linked List** — โครงสร้างข้อมูลที่เก็บสมาชิกเป็น **Node (โหนด)** แยกกัน กระจัดกระจายอยู่ที่ไหนก็ได้ใน Heap โดยแต่ละ Node เก็บ **ค่าข้อมูล (value)** และ **pointer/reference ชี้ไปยัง Node ถัดไป** (เชื่อมโยงกับแนวคิด Pointer จากบทที่ 8)
- **Singly Linked List** — แต่ละ Node ชี้ไปข้างหน้าทางเดียวเท่านั้น (ไปยัง node ถัดไป)
- **Doubly Linked List** — แต่ละ Node ชี้ได้ทั้งไปข้างหน้า (next) และย้อนกลับ (prev)
- **Head/Tail** — Head คือ Node แรกสุดของลิสต์ (จุดเริ่มต้นเข้าถึงทั้งหมด), Tail คือ Node สุดท้าย (มัก `next` ชี้ไปที่ `None`/`null`)

## ทำไมต้องมีสิ่งนี้ (Why it exists)

- **แก้ปัญหาการแทรก/ลบที่ช้าของ Array**: เพราะ Node ไม่จำเป็นต้องอยู่ติดกันในหน่วยความจำ การแทรก/ลบตรงกลางลิสต์แค่ "เปลี่ยนทิศทางของ pointer" 2-3 ตัว โดยไม่ต้องเลื่อนข้อมูลที่เหลือทั้งหมดเหมือน Array — ทำให้เป็น **O(1)** ถ้ารู้ตำแหน่ง Node นั้นอยู่แล้ว
- **ไม่ต้องรู้ขนาดล่วงหน้าและไม่ต้องขยายขนาดแบบ copy ทั้งชุด**: ต่างจาก Dynamic Array ที่บางครั้งต้อง copy สมาชิกทั้งหมดไปที่ใหม่เมื่อเต็ม (บทที่ 12) Linked List แค่สร้าง Node ใหม่แล้วเชื่อม pointer เข้าไป ไม่ต้องแตะสมาชิกเดิมเลย
- **เป็นรากฐานของโครงสร้างข้อมูลอื่นอีกมากมาย**: Stack, Queue, และแม้แต่ Tree/Graph (บทถัดๆ ไป) ล้วนใช้แนวคิด "Node ที่เชื่อมกันด้วย pointer" แบบเดียวกับ Linked List เป็นพื้นฐาน

## เปรียบเทียบกับชีวิตจริง (Real-world analogy)

- **Array** เหมือน **ที่นั่งในโรงหนังที่เรียงติดกันเป็นแถว** — รู้เลขที่นั่งก็เดินตรงไปนั่งได้ทันที แต่ถ้าต้องการแทรกเก้าอี้ใหม่ตรงกลางแถว ต้องขยับทุกคนในแถวนั้นทั้งหมด
- **Linked List** เหมือน **เกมล่าสมบัติ (Treasure Hunt)** — แต่ละจุดจะมีข้อความบอกว่า "จุดต่อไปอยู่ที่ไหน" คุณเริ่มจากจุดแรก (Head) แล้วเดินตามคำใบ้ไปทีละจุดจนถึงจุดที่ต้องการ **ไม่มีทางกระโดดไปจุดที่ 5 ได้ทันทีโดยไม่ผ่านจุดที่ 1-4 ก่อน** แต่การ "แทรกจุดใหม่" เข้าไปกลางเส้นทางทำได้ง่ายมาก แค่เปลี่ยนคำใบ้ของจุดก่อนหน้าให้ชี้ไปยังจุดใหม่แทน

## แผนภาพอธิบาย (Visual explanation)

### โครงสร้าง Singly Linked List

```
HEAD                                                    TAIL
 │                                                        │
 ▼                                                        ▼
┌──────┬──────┐    ┌──────┬──────┐    ┌──────┬──────┐
│ 10   │ next ●───►│ 20   │ next ●───►│ 30   │ None │
└──────┴──────┘    └──────┴──────┘    └──────┴──────┘
  Node 1              Node 2              Node 3

แต่ละ Node กระจัดกระจายอยู่ที่ไหนก็ได้ใน Heap เช่น:
  Node 1 อยู่ที่ address 0x500
  Node 2 อยู่ที่ address 0x120   <- ไม่ติดกับ Node 1 เลย!
  Node 3 อยู่ที่ address 0x900
(ต่างจาก Array ที่บทก่อนเก็บติดกันเป็นแถวเดียว)
```

### การเข้าถึงสมาชิก — ทำไมช้า O(n)

```
ต้องการ Node ที่ 3 (ค่า 30):
  เริ่มจาก HEAD -> Node 1 (10) -> ตาม next -> Node 2 (20) -> ตาม next -> Node 3 (30)
  ต้อง "เดินตาม pointer" ทีละสเต็ป ไล่จาก Head เสมอ ไม่มีทางกระโดดตรงไปได้
  -> O(n) ในกรณีแย่ที่สุด (ต่างจาก Array ที่ arr[2] เข้าถึงได้ทันที O(1))
```

### การแทรก Node — ทำไมเร็ว O(1) (เมื่อรู้ตำแหน่งแล้ว)

```
ก่อนแทรก:   [10] -> [20] -> [30]

ต้องการแทรก 99 ระหว่าง 10 กับ 20:

  1. สร้าง Node ใหม่:  [99]
  2. ให้ [99].next ชี้ไปที่ [20]   (เดิมที่ [10].next ชี้อยู่)
  3. ให้ [10].next ชี้ไปที่ [99] แทน

หลังแทรก:   [10] -> [99] -> [20] -> [30]

แค่เปลี่ยน pointer 2 เส้น -> ไม่ต้องเลื่อนข้อมูลใดๆ เลย!
(ต่างจาก Array ที่ต้องเลื่อนสมาชิกทั้งหมดที่อยู่หลังตำแหน่งแทรก)
```

### Singly vs Doubly Linked List

```
Singly:   [10]─►[20]─►[30]─►None                (ชี้ไปข้างหน้าทางเดียว)

Doubly:   None◄─[10]◄─►[20]◄─►[30]─►None          (ชี้ได้ทั้งสองทาง)
              prev/next    prev/next
```

## ตัวอย่างโค้ด (Code example)

```python
class Node:
    def __init__(self, value):
        self.value = value
        self.next = None          # เริ่มต้นยังไม่ชี้ไปไหน

class LinkedList:
    def __init__(self):
        self.head = None           # ลิสต์ว่าง -> ไม่มี Node เลย

    def append(self, value):        # เพิ่มที่ท้ายลิสต์
        new_node = Node(value)
        if self.head is None:
            self.head = new_node
            return
        current = self.head
        while current.next is not None:   # เดินตาม pointer จนถึง Node สุดท้าย
            current = current.next
        current.next = new_node             # เชื่อม Node สุดท้ายเดิมเข้ากับ Node ใหม่

    def insert_after(self, target_value, new_value):   # แทรกหลัง Node ที่มีค่าที่ระบุ
        current = self.head
        while current is not None:
            if current.value == target_value:
                new_node = Node(new_value)
                new_node.next = current.next    # Node ใหม่ชี้ไปยังสิ่งที่ current เคยชี้
                current.next = new_node          # current ชี้ไปยัง Node ใหม่แทน
                return
            current = current.next

    def print_all(self):
        current = self.head
        while current is not None:
            print(current.value, end=" -> ")
            current = current.next
        print("None")

ll = LinkedList()
ll.append(10)
ll.append(20)
ll.append(30)
ll.print_all()               # 10 -> 20 -> 30 -> None

ll.insert_after(10, 99)
ll.print_all()               # 10 -> 99 -> 20 -> 30 -> None
```

## ทำงานทีละขั้นตอน (Step-by-step execution)

1. `ll.append(10)` — เพราะ `self.head` เป็น `None` (ลิสต์ว่าง) โปรแกรมสร้าง `Node(10)` แล้วให้ `self.head` ชี้ไปที่ Node นี้โดยตรง — นี่คือ Node แรกและ Node เดียวในลิสต์ตอนนี้
2. `ll.append(20)` — คราวนี้ `self.head` ไม่ใช่ None แล้ว โปรแกรมเริ่ม `current = self.head` แล้ว**เดินตาม `.next` ไปเรื่อยๆ** จนกว่า `current.next` จะเป็น `None` (เจอ Node สุดท้าย) แล้วจึงเชื่อม `current.next` ไปยัง `Node(20)` ใหม่ — สังเกตว่าต้องเดินผ่านทุก Node ก่อนถึงจะรู้ว่า Node ไหนคือตัวสุดท้าย (O(n) สำหรับ append ในการออกแบบนี้ — ถ้าต้องการ append แบบ O(1) ต้องเก็บ pointer ไปยัง `tail` แยกไว้ต่างหาก)
3. `ll.insert_after(10, 99)` — โปรแกรมเดินหา Node ที่มีค่า `10` ก่อน (O(n) ในกรณีแย่สุด) เมื่อเจอแล้ว **สร้าง `Node(99)` ใหม่ ให้ `new_node.next` ชี้ไปยังสิ่งที่ `current.next` เคยชี้อยู่ (คือ Node ที่มีค่า 20) ก่อน** แล้วจึงเปลี่ยน `current.next` ให้ชี้มาที่ `new_node` แทน — ลำดับการเปลี่ยน pointer นี้สำคัญมาก ถ้าสลับลำดับ (เปลี่ยน `current.next` ก่อน) จะทำให้ **สูญเสีย reference ไปยัง Node ที่เหลือของลิสต์ทันที** (เข้าถึง Node 20, 30 ไม่ได้อีกเลย)

## Time Complexity

| Operation | Complexity | เหตุผล |
|---|---|---|
| เข้าถึงสมาชิกด้วยตำแหน่ง (เช่น "ตัวที่ 5") | O(n) | ต้องเดินตาม pointer ทีละ Node จาก Head |
| ค้นหาค่า | O(n) | ต้องไล่ตรวจทีละ Node เช่นเดียวกับ Array |
| แทรก/ลบเมื่อรู้ตำแหน่ง Node แล้ว (มี reference อยู่ในมือ) | O(1) | แค่เปลี่ยน pointer ไม่ต้องเลื่อนข้อมูล |
| แทรกที่ต้นลิสต์ (Head) | O(1) | ไม่ต้องเดินหาตำแหน่งเลย |
| แทรกที่ท้ายลิสต์ (ไม่มี tail pointer) | O(n) | ต้องเดินหา Node สุดท้ายก่อน |

## Space Complexity

Linked List ใช้พื้นที่ **O(n)** ตามจำนวนสมาชิก เช่นเดียวกับ Array แต่มี **overhead เพิ่มต่อสมาชิก** เพราะแต่ละ Node ต้องเก็บ pointer เพิ่มอย่างน้อย 1 ตัว (Singly) หรือ 2 ตัว (Doubly) นอกเหนือจากค่าข้อมูลจริง ทำให้ใช้หน่วยความจำมากกว่า Array ที่เก็บค่าเปล่าๆ ติดกัน

## ข้อดี (Advantages)

- แทรก/ลบที่ต้นลิสต์หรือตำแหน่งที่รู้ pointer อยู่แล้วเร็วมาก O(1) ไม่ต้องเลื่อนข้อมูล
- ไม่ต้องจองพื้นที่ต่อเนื่องล่วงหน้า ขยายขนาดได้ทีละ Node โดยไม่ต้อง copy ข้อมูลเดิมทั้งชุด (ต่างจาก Dynamic Array)
- เหมาะกับข้อมูลที่ขนาดเปลี่ยนแปลงบ่อยและไม่รู้ขนาดสูงสุดล่วงหน้า

## ข้อเสีย (Disadvantages)

- เข้าถึงสมาชิกด้วยตำแหน่ง (index) ช้า O(n) — ไม่มีทาง "กระโดดตรง" ไปยังตำแหน่งใดๆ ได้ทันทีเหมือน Array
- ใช้หน่วยความจำมากกว่า Array ต่อสมาชิกหนึ่งตัว (ต้องเก็บ pointer เพิ่ม)
- ไม่ cache-friendly เท่า Array เพราะ Node กระจัดกระจายในหน่วยความจำ ไม่ติดกัน (ตามหลักการ CPU cache จากบทที่ 1 — sequential access ของ array เร็วกว่าการเดินตาม pointer ของ linked list มาก แม้ทั้งคู่จะเป็น "O(n)" เท่ากันในทางทฤษฎี)

## การใช้งานจริง (Real-world usage)

- ใช้เป็นโครงสร้างภายในของ Stack และ Queue (บทถัดไป) ที่ต้องเพิ่ม/ลบที่ปลายด้านใดด้านหนึ่งบ่อยๆ
- Music/Video playlist ที่ต้องเพิ่ม/ลบ/จัดเรียงเพลงบ่อย โดยไม่ต้องรู้จำนวนเพลงทั้งหมดล่วงหน้า
- Undo/Redo history ในโปรแกรมแก้ไขเอกสาร (Doubly Linked List เดินหน้า-ถอยหลังได้)
- Browser history (เดินหน้า-ถอยหลังหน้าเว็บ) มักใช้แนวคิด Doubly Linked List

## แนวทางปฏิบัติที่ดี (Best Practices)

- ถ้าต้องเข้าถึงสมาชิกด้วย index บ่อยๆ ให้ใช้ Array/Dynamic Array แทน Linked List (Linked List ไม่เหมาะกับ random access)
- เก็บ pointer ไปยัง `tail` แยกต่างหากถ้าต้อง append ที่ท้ายลิสต์บ่อยๆ เพื่อให้ append เป็น O(1) แทนที่จะต้องเดินหา Node สุดท้ายทุกครั้ง
- ระวังการ**เปลี่ยนลำดับการปรับ pointer** เวลาแทรก/ลบ Node — ต้องผูก pointer ใหม่เข้าที่ก่อนตัดการเชื่อมต่อเดิม ไม่งั้นจะสูญเสีย reference ไปยังส่วนที่เหลือของลิสต์อย่างถาวร

## ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

- ลืมอัปเดต pointer ตามลำดับที่ถูกต้องตอนแทรก/ลบ Node ทำให้ลิสต์ขาดครึ่งหนึ่งหายไปอย่างกู้คืนไม่ได้ (ตามที่อธิบายในขั้นตอนที่ 3 ด้านบน)
- ลืมจัดการกรณีลิสต์ว่าง (`head is None`) เป็นพิเศษ ทำให้โปรแกรม error เมื่อเรียกใช้กับลิสต์ที่ยังไม่มีสมาชิกเลย
- พยายามเข้าถึงสมาชิกด้วย index เหมือน Array (`list[5]`) ทั้งที่ Linked List ไม่รองรับการเข้าถึงแบบนั้นโดยตรง ต้องเขียน loop เดินไล่เอง
- ใน Singly Linked List พยายามเดินย้อนกลับ (หา Node ก่อนหน้า) ซึ่งทำไม่ได้เลยถ้าไม่มี `prev` pointer (ต้องใช้ Doubly Linked List แทน)

## คำถามสัมภาษณ์งาน (Interview Questions)

1. อธิบายความแตกต่างระหว่าง Array และ Linked List ในแง่ time/space complexity ของแต่ละ operation
2. ทำไมการแทรก Node กลาง Linked List ถึงเป็น O(1) แต่การแทรกกลาง Array ถึงเป็น O(n)?
3. Singly Linked List ต่างจาก Doubly Linked List อย่างไร แต่ละแบบเหมาะกับสถานการณ์ไหน?
4. ทำไม Linked List ถึง cache-unfriendly กว่า Array แม้ time complexity ของการไล่ทุกสมาชิกจะเป็น O(n) เท่ากัน?
5. เขียนฟังก์ชันตรวจสอบว่า Linked List มี cycle (วนกลับมาซ้ำ) หรือไม่ (คำถามคลาสสิก — ใบ้: Floyd's Cycle Detection / "เต่ากับกระต่าย")

## แบบฝึกหัด (Practice Exercises)

1. เขียนฟังก์ชัน `delete(value)` ให้กับ `LinkedList` class ด้านบน ที่ลบ Node แรกที่มีค่าตรงกับที่ระบุออกจากลิสต์
2. เขียนฟังก์ชัน `reverse()` ที่กลับด้าน Linked List ทั้งหมด (เปลี่ยนทิศทางของทุก pointer ในลิสต์ โดยไม่สร้างลิสต์ใหม่)
3. เขียนฟังก์ชันหา Node ตรงกลาง (middle) ของ Linked List โดยเดินผ่านลิสต์แค่รอบเดียว (ใบ้: ใช้ตัวชี้ 2 ตัวที่เดินเร็วช้าต่างกัน — "slow and fast pointer")

## Mini Project

**"Music Playlist Manager"**: เขียนโปรแกรมที่ใช้ Linked List (Doubly Linked List) จัดการเพลย์ลิสต์เพลง:
1. รองรับคำสั่งเพิ่มเพลงต่อท้าย, แทรกเพลงหลังเพลงที่ระบุ, และลบเพลงตามชื่อ
2. รองรับคำสั่ง "เล่นเพลงถัดไป" และ "เล่นเพลงก่อนหน้า" โดยใช้ `next`/`prev` pointer ของ Doubly Linked List
3. เปรียบเทียบกับการ implement เพลย์ลิสต์เดียวกันด้วย Array/List ธรรมดา แล้ววัดเวลาการแทรกเพลงที่ตำแหน่งกลางเพลย์ลิสต์ขนาดใหญ่ (เช่น 100,000 เพลง) เทียบกันทั้งสองแบบ เพื่อพิสูจน์ความแตกต่างของ time complexity ที่เรียนมา

## ข้อคิดสำคัญ (Key Takeaways)

- Linked List เก็บข้อมูลเป็น Node ที่กระจัดกระจายในหน่วยความจำ เชื่อมกันด้วย pointer แทนที่จะอยู่ติดกันแบบ Array
- แทรก/ลบเร็วมาก O(1) เมื่อรู้ตำแหน่ง Node อยู่แล้ว แต่เข้าถึงด้วยตำแหน่ง (index) ช้า O(n) เพราะต้องเดินตาม pointer ทีละสเต็ป
- Singly Linked List ชี้ทางเดียว ส่วน Doubly Linked List ชี้ได้สองทาง แลกกับการใช้หน่วยความจำมากขึ้น
- Linked List ไม่ cache-friendly เท่า Array เพราะข้อมูลไม่ได้อยู่ติดกัน แม้ Big O จะดูเหมือนกันในบาง operation
- Linked List เป็นรากฐานสำคัญของ Stack และ Queue ที่จะเรียนในบทถัดไป ซึ่งเป็นโครงสร้างข้อมูลที่จำกัดวิธีเข้าถึงข้อมูลให้เฉพาะเจาะจงมากขึ้นเพื่อประโยชน์เฉพาะทาง
