# บทที่ 10: Conditionals — if, else, switch

## แนวคิดหลัก (Concept)

จนถึงตอนนี้โปรแกรมของเรา "ทำงานทีละบรรทัดจากบนลงล่างเสมอ" แต่โปรแกรมจริงต้อง**ตัดสินใจ**ว่าจะทำอะไรขึ้นอยู่กับเงื่อนไข — นี่คือหัวใจของ **Control Flow (การควบคุมทิศทางการทำงาน)** บทแรก

- **if** — ทำงานเฉพาะเมื่อเงื่อนไข (expression ที่ประเมินเป็น boolean จากบทที่ 6) เป็น True
- **else** — ทำงานเมื่อเงื่อนไขของ `if` เป็น False
- **else if / elif** — ตรวจสอบเงื่อนไขถัดไปเมื่อเงื่อนไขก่อนหน้าเป็น False
- **switch / match** — เปรียบเทียบค่าตัวแปรเดียวกับหลายๆ ค่าที่เป็นไปได้ ทางเลือกที่กระชับกว่าเมื่อมี `if/elif` จำนวนมากที่เปรียบเทียบตัวแปรเดียวกัน

## ทำไมต้องมีสิ่งนี้ (Why it exists)

- **โลกจริงเต็มไปด้วยการตัดสินใจ**: โปรแกรมที่ทำงานเหมือนกันทุกครั้งไม่ว่า input จะเป็นอะไรไม่มีประโยชน์ — ระบบต้อง "แตกทาง" การทำงานตามสถานการณ์ (อายุเกิน 18 ปีหรือไม่, login สำเร็จหรือไม่, สินค้ามีในสต็อกหรือไม่)
- **if/else คือการนำ Boolean Expression (จากบทที่ 6) มาใช้ควบคุมทิศทางจริง**: นี่คือจุดที่ comparison operator (`>`, `==`) และ logical operator (`and`, `or`) ที่เรียนไปกลายเป็นเครื่องมือตัดสินใจ ไม่ใช่แค่คำนวณค่า boolean เฉยๆ
- **switch/match มีไว้เพื่อความอ่านง่ายเมื่อเทียบค่าเดียวกับหลายทางเลือก**: เขียน `if x == 1 ... elif x == 2 ... elif x == 3` ซ้ำๆ อ่านยากกว่าและเสี่ยงพิมพ์ตัวแปรผิดในแต่ละ elif เมื่อเทียบกับ `switch(x)` ที่ระบุตัวแปรครั้งเดียว

## เปรียบเทียบกับชีวิตจริง (Real-world analogy)

- **if/else** เหมือน **ป้ายทางแยกบนถนน** — ถ้าฝนตก (เงื่อนไข True) ให้เลี้ยวเข้าทางหลังคา ถ้าไม่ตก (False) ให้ตรงไปทางลัด คุณเลือกได้แค่ทางเดียวในแต่ละครั้ง
- **switch/match** เหมือน **เครื่องหยอดเหรียญขายของ** — กดปุ่ม A1 ได้ขนมชนิดหนึ่ง กดปุ่ม A2 ได้อีกชนิดหนึ่ง เครื่องเทียบเลขปุ่มที่กด (ค่าตัวแปรเดียว) กับรายการที่ตั้งไว้ทั้งหมด แล้วเลือกทางที่ตรงกัน

## แผนภาพอธิบาย (Visual explanation)

### if / elif / else — ผังการทำงาน

```
                    ┌───────────────┐
                    │  ตรวจสอบ age   │
                    └───────┬───────┘
                            │
              ┌─────────────┼─────────────┐
              ▼             ▼             ▼
       age < 13        13<=age<18    age >= 18
       (if)             (elif)        (else)
          │                │              │
          ▼                ▼              ▼
     "เด็ก"            "วัยรุ่น"        "ผู้ใหญ่"

หมายเหตุ: ตรวจสอบตามลำดับบนลงล่าง เจอเงื่อนไขแรกที่ True แล้วหยุดทันที
         (เงื่อนไขถัดไปจะไม่ถูกตรวจสอบอีกเลย แม้จะเป็น True ก็ตาม)
```

### switch/match — เทียบค่าเดียวกับหลายทางเลือก

```
switch (day) {
    case 1: return "จันทร์";
    case 2: return "อังคาร";
    ...
    default: return "ไม่ทราบ";     ← เหมือน "else" ใน if/else
}

เทียบกับการเขียนแบบ if/elif ที่ต้องพิมพ์ "day ==" ซ้ำทุกบรรทัด:
    if day == 1: return "จันทร์"
    elif day == 2: return "อังคาร"
    ...
```

### Truthy / Falsy — ค่าที่ถือว่าเป็น False โดยปริยาย (พบใน Python, JS)

```
False โดยปริยาย (falsy):    0,  0.0,  "",  [],  {},  None/null,  False
True โดยปริยาย (truthy):    ค่าอื่นๆ ทั้งหมด (รวมถึง "0" ที่เป็น string ไม่ว่าง!)

if []:          # False -> ไม่ทำงาน (list ว่าง)
    print("มีของ")
if [0]:         # True -> ทำงาน! (list มี 1 สมาชิก แม้สมาชิกนั้นจะเป็น 0)
    print("มีของ")
```

## ตัวอย่างโค้ด (Code example)

```python
# ===== if / elif / else =====
def classify_age(age):
    if age < 13:
        return "เด็ก"
    elif age < 18:
        return "วัยรุ่น"
    else:
        return "ผู้ใหญ่"

print(classify_age(10))   # เด็ก
print(classify_age(15))   # วัยรุ่น
print(classify_age(25))   # ผู้ใหญ่

# ===== เงื่อนไขซับซ้อน (logical operators จากบทที่ 6) =====
def can_enter_club(age, has_id):
    if age >= 18 and has_id:
        return "เข้าได้"
    return "เข้าไม่ได้"

# ===== match-case (Python 3.10+) เทียบเท่า switch =====
def day_name(day_number):
    match day_number:
        case 1:
            return "จันทร์"
        case 2:
            return "อังคาร"
        case 3:
            return "พุธ"
        case _:                  # "_" เทียบเท่า "default" -> จับทุกกรณีที่เหลือ
            return "ไม่ทราบ"

print(day_name(2))    # อังคาร
print(day_name(99))   # ไม่ทราบ

# ===== Ternary / Conditional Expression (if แบบสั้นในบรรทัดเดียว) =====
age = 20
status = "ผู้ใหญ่" if age >= 18 else "เด็ก"    # expression ที่ให้ค่าได้เลย ไม่ใช่แค่ statement
```

## ทำงานทีละขั้นตอน (Step-by-step execution)

1. `classify_age(15)` — Python ประเมิน `age < 13` (15 < 13 = False) ก่อน จึงข้ามไปตรวจ `elif age < 18` (15 < 18 = True) → คืนค่า `"วัยรุ่น"` ทันที **โดยไม่ตรวจ `else` ต่อเลย** เพราะเจอเงื่อนไขที่ True แล้ว
2. `can_enter_club(20, True)` — ด้วย **short-circuit evaluation** (จากบทที่ 6) Python ตรวจ `age >= 18` ก่อน (True) แล้วจึงตรวจ `has_id` ต่อ (True) ผลลัพธ์ของ `and` จึงเป็น True → คืนค่า `"เข้าได้"`
3. `day_name(2)` — คำสั่ง `match` เทียบค่า `day_number` (ตัวแปรเดียว) กับแต่ละ `case` ตามลำดับ พบว่าตรงกับ `case 2` จึงคืนค่า `"อังคาร"` ทันที โดยไม่ตรวจ `case` ที่เหลือ
4. `status = "ผู้ใหญ่" if age >= 18 else "เด็ก"` — นี่คือ **conditional expression** (หรือ ternary operator ในภาษาอื่นเช่น `age >= 18 ? "ผู้ใหญ่" : "เด็ก"` ใน C/JavaScript) ซึ่งต่างจาก `if` statement ทั่วไปตรงที่**ให้ค่ากลับมาได้โดยตรง** สามารถนำไป assign ให้ตัวแปรในบรรทัดเดียวได้ (เชื่อมโยงกับแนวคิด Expression vs Statement จากบทที่ 6)

## Time Complexity

การประเมินเงื่อนไข `if/elif/else` แต่ละอันเป็น **O(1)** ต่อการเปรียบเทียบหนึ่งครั้ง แต่ถ้ามี `elif` ต่อกันจำนวนมาก (n เงื่อนไข) ในกรณีที่แย่ที่สุด (worst case) ต้องตรวจสอบทั้งหมด n ครั้งก่อนจะเจอเงื่อนไขที่ตรง จึงเป็น **O(n)** ในกรณีนั้น — `switch/match` ในบางภาษา (เช่น C ที่ compiler แปลงเป็น jump table) อาจทำได้เร็วถึง O(1) โดยไม่ต้องตรวจทีละเงื่อนไข

## Space Complexity

Conditional statement เองไม่ใช้พื้นที่หน่วยความจำเพิ่มเติมอย่างมีนัยสำคัญ (O(1)) เพราะเป็นแค่การควบคุมทิศทางการทำงาน ไม่ได้สร้างข้อมูลใหม่

## แนวทางปฏิบัติที่ดี (Best Practices)

- เรียงลำดับเงื่อนไขจาก**เฉพาะเจาะจงที่สุดไปหากว้างที่สุด** เพื่อป้องกันเงื่อนไขที่กว้างกว่าดักจับเงื่อนไขที่ควรเฉพาะเจาะจงกว่าไปก่อน
- ใช้ `elif`/`switch` แทนการเขียน `if` แยกกันหลายก้อนเมื่อเงื่อนไขทั้งหมด**เทียบตัวแปรเดียวกัน** เพื่อความชัดเจนและประสิทธิภาพ
- หลีกเลี่ยงการซ้อน `if` ลึกเกินไป (nested if) — ควรใช้ **early return** (คืนค่าออกจากฟังก์ชันทันทีเมื่อเจอเงื่อนไขที่ไม่ผ่าน) เพื่อลดระดับการซ้อนและทำให้อ่านง่ายขึ้น
- ใน Python ระวังเรื่อง truthy/falsy ของ container ว่าง (`[]`, `{}`, `""`) ที่ถือเป็น False โดยปริยาย

## ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

- ใช้ `if` แยกหลายก้อนแทนที่จะใช้ `elif` เมื่อเงื่อนไขไม่ควรทำงานพร้อมกัน ทำให้ตรวจสอบเงื่อนไขที่ไม่จำเป็นต่อไปแม้เจอคำตอบแล้ว (เสียประสิทธิภาพและอาจเกิดบั๊กถ้าหลายเงื่อนไขเป็นจริงพร้อมกันโดยไม่ตั้งใจ)
- ลืมเคส `else`/`default` ทำให้บางกรณี (edge case) ไม่ถูกจัดการเลย
- เขียนเงื่อนไขซ้อนกันลึกเกินไป (nested if ภายใน if ภายใน if) ทำให้อ่านและ debug ยากมาก
- สับสนระหว่าง `and`/`or` (ต้องผ่านทั้งคู่ หรือผ่านอย่างน้อยหนึ่ง) ทำให้เขียนเงื่อนไขผิดตรรกะโดยไม่รู้ตัว เช่น เขียน `if age < 13 or age < 18` แทนที่จะใช้ `elif` ทำให้เงื่อนไขที่สองครอบคลุมเงื่อนไขแรกอยู่แล้วโดยไม่จำเป็น

## ข้อคิดสำคัญ (Key Takeaways)

- if/elif/else ควบคุมทิศทางโปรแกรมตามเงื่อนไข ตรวจสอบตามลำดับบนลงล่างและหยุดทันทีที่เจอเงื่อนไขแรกที่เป็น True
- switch/match เหมาะกับการเทียบตัวแปรเดียวกับหลายค่าที่เป็นไปได้ อ่านง่ายกว่า if/elif ต่อเนื่องยาวๆ
- Early return ช่วยลดการซ้อนเงื่อนไขลึกเกินไป ทำให้โค้ดอ่านง่ายขึ้นอย่างมาก
- Conditional expression (ternary) ให้ค่ากลับมาโดยตรง ต่างจาก if statement ที่เป็นแค่การควบคุมทิศทาง
- ต้องระวังเรื่อง truthy/falsy ในภาษาที่ไม่ต้องเปรียบเทียบกับ boolean ตรงๆ (Python, JavaScript) เพราะอาจทำให้เกิดบั๊กที่ไม่คาดคิด
- บทถัดไปจะต่อยอดเรื่อง Loops ซึ่งใช้เงื่อนไข (boolean expression) แบบเดียวกันนี้มาควบคุมว่าจะทำงานซ้ำไปเรื่อยๆ นานแค่ไหน
