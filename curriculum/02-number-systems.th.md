# บทที่ 2: เลขฐาน, ไบนารี, เฮกซาเดซิมัล, ASCII และ Unicode

## แนวคิดหลัก (Concept)

คอมพิวเตอร์ไม่เข้าใจตัวเลข ตัวอักษร หรือรูปภาพแบบที่มนุษย์เห็น — ภายในเครื่องมีแค่ **สัญญาณไฟฟ้า 2 สถานะ**: มีไฟ (1) กับ ไม่มีไฟ (0) ทุกสิ่งที่คอมพิวเตอร์เก็บหรือประมวลผล ไม่ว่าจะเป็นตัวเลข ข้อความ รูปภาพ เสียง หรือวิดีโอ สุดท้ายแล้วถูกเข้ารหัสเป็นลำดับของ 0 และ 1 ทั้งหมด นี่คือ **เลขฐานสอง (Binary / Base 2)**

นอกจากฐาน 2 แล้ว โปรแกรมเมอร์ยังใช้ฐานเลขอื่นเป็นเครื่องมือช่วยอ่าน/เขียนค่าไบนารีให้กระชับขึ้น:

- **ฐาน 2 (Binary)** — ใช้ตัวเลข 0-1 → ภาษาจริงของฮาร์ดแวร์
- **ฐาน 10 (Decimal)** — ใช้ตัวเลข 0-9 → ภาษาที่มนุษย์คุ้นเคย
- **ฐาน 16 (Hexadecimal)** — ใช้ 0-9 และ A-F → ย่อไบนารีให้สั้นลง มักใช้แทนสี, memory address, hash

ส่วน **ASCII** และ **Unicode** คือระบบที่กำหนดว่า "ตัวเลขไบนารีชุดไหน แทนตัวอักษรอะไร" เช่น เลข 65 (หรือ `01000001` ในไบนารี) ถูกตกลงกันไว้ว่าคือตัวอักษร `A`

## ทำไมต้องมีสิ่งนี้ (Why it exists)

- **ฮาร์ดแวร์ทำได้แค่ 2 สถานะ**: ทรานซิสเตอร์ในชิปเป็นสวิตช์ไฟฟ้า เปิด/ปิด เท่านั้น ไม่มีสถานะที่ 3 ดังนั้นระบบเลขฐาน 2 จึงเป็นภาษาธรรมชาติของฮาร์ดแวร์ ไม่ใช่ทางเลือก
- **เฮกซาเดซิมัลมีไว้เพื่อมนุษย์**: ไบนารี 8 หลัก (1 byte) เขียนยาวและอ่านยาก (`01001010`) แต่แปลงเป็นฐาน 16 ได้แค่ 2 หลัก (`4A`) เพราะ 16 = 2⁴ ทำให้แปลงกลับไปกลับมากับไบนารีง่ายมาก (ทุก 4 บิต = เลขฐาน 16 หนึ่งหลักพอดี)
- **ASCII/Unicode มีไว้เพื่อให้ทุกเครื่องตีความตัวอักษรตรงกัน**: ถ้าไม่มีมาตรฐานร่วมกัน คอมพิวเตอร์เครื่อง A อาจตีความเลข 65 เป็น "A" แต่เครื่อง B ตีความเป็น "ก" ทำให้ข้อความเพี้ยนเมื่อส่งไฟล์ข้ามเครื่อง

## เปรียบเทียบกับชีวิตจริง (Real-world analogy)

- **ไบนารี** เหมือน **สวิตช์ไฟ** ในบ้าน — แต่ละดวงมีแค่ 2 สถานะ (เปิด/ปิด) ถ้ามีสวิตช์ 8 ดวงเรียงกัน คุณสามารถแทนค่าตัวเลขได้ 256 แบบ (2⁸) จากรูปแบบเปิด-ปิดที่ต่างกัน
- **เฮกซาเดซิมัล** เหมือน **การเขียนเบอร์โทรศัพท์แบบย่อ** — แทนที่จะเขียนไบนารียาวๆ เราแบ่งเป็นกลุ่มละ 4 บิตแล้วเขียนแทนด้วยสัญลักษณ์เดียว สั้นลง อ่านง่ายขึ้น แต่ความหมายเดิมไม่เปลี่ยน
- **ASCII/Unicode** เหมือน **รหัสธงสัญญาณของกองทัพเรือ** — ทุกฝ่ายต้องตกลงกันล่วงหน้าว่า "ธงแบบนี้ = ตัวอักษรอะไร" ถ้าฝั่งหนึ่งใช้รหัสคนละชุดกับอีกฝั่ง ข้อความจะสื่อสารกันไม่รู้เรื่อง

## แผนภาพอธิบาย (Visual explanation)

### การนับเลขฐาน 2

```
ฐาน 10:   ...  1000    100    10     1
ฐาน 2:    ...  1000    100    10     1   (เลขฐาน 2 เอง)
                (8)    (4)    (2)   (1)   ← ค่าจริงของแต่ละหลัก (ฐาน 10)

ตัวอย่าง: เลขฐาน 2 = 1011
           หลักที่:   8   4   2   1
           บิต:       1   0   1   1
           คำนวณ:    8 + 0 + 2 + 1 = 11 (ฐาน 10)
```

### ความสัมพันธ์ระหว่าง ฐาน 2, ฐาน 16 และ 1 ไบต์ (8 บิต)

```
ไบนารี (8 บิต):   0100   1010
                    │       │
                    ▼       ▼
เฮกซาเดซิมัล:        4       A     →  เขียนรวมว่า "4A"

1 ไบต์ (byte) = 8 บิต = เลขฐาน 16 สองหลักพอดี
1 บิต (bit) = สถานะเดียว (0 หรือ 1)
```

### ตารางเทียบฐาน

| ฐาน 2 (Binary) | ฐาน 10 (Decimal) | ฐาน 16 (Hex) |
|---|---|---|
| 0000 | 0 | 0 |
| 0001 | 1 | 1 |
| 1001 | 9 | 9 |
| 1010 | 10 | A |
| 1111 | 15 | F |
| 11111111 | 255 | FF |

### ASCII vs Unicode

```
ASCII (7 บิต, 128 ตัวอักษร)      →  ครอบคลุมแค่ภาษาอังกฤษ + สัญลักษณ์พื้นฐาน
   'A' = 65 = 01000001

Unicode / UTF-8 (แปรผัน 8-32 บิต) →  ครอบคลุมทุกภาษาในโลก รวมอิโมจิ
   'A' = U+0041  (เก็บแบบเดียวกับ ASCII เพื่อความเข้ากันได้)
   'ก' = U+0E01  (ภาษาไทย ต้องใช้มากกว่า 1 ไบต์)
   '😀' = U+1F600 (อิโมจิ ต้องใช้ 4 ไบต์ใน UTF-8)
```

## ตัวอย่างโค้ด (Code example)

```python
# แปลงเลขฐาน 10 เป็นฐาน 2 และฐาน 16
n = 74
print(bin(n))   # '0b1001010'  -> ไบนารีของ 74
print(hex(n))   # '0x4a'       -> เฮกซาของ 74

# แปลงกลับจากฐาน 2 และฐาน 16 เป็นฐาน 10
print(int('1001010', 2))   # 74
print(int('4a', 16))       # 74

# ดูรหัส ASCII/Unicode ของตัวอักษร
print(ord('A'))    # 65
print(ord('ก'))    # 3585 (0xE01 ในฐาน 16)
print(chr(65))     # 'A'

# ดูว่า 1 ตัวอักษรใช้กี่ไบต์เมื่อเข้ารหัสแบบ UTF-8
print(len('A'.encode('utf-8')))    # 1 ไบต์
print(len('ก'.encode('utf-8')))    # 3 ไบต์
print(len('😀'.encode('utf-8')))   # 4 ไบต์
```

## ทำงานทีละขั้นตอน (Step-by-step execution)

1. `bin(74)` — Python นำ 74 (ฐาน 10) มาหารด้วย 2 ซ้ำๆ เก็บเศษไว้ แล้วอ่านเศษจากล่างขึ้นบน ได้ `1001010` → เพราะ 64+8+2 = 74 (บิตที่ 6 และ 3 และ 1 เป็น 1)
2. `hex(74)` — แบ่งไบนารี `01001010` ออกเป็นกลุ่มละ 4 บิต: `0100` และ `1010` → แปลงแต่ละกลุ่มเป็นฐาน 16 ได้ `4` และ `A` → รวมเป็น `4a`
3. `ord('ก')` — ตัวอักษร "ก" มีจุดรหัส (code point) ใน Unicode คือ U+0E01 ซึ่งเท่ากับ 3585 ในฐาน 10
4. `'ก'.encode('utf-8')` — UTF-8 เป็นวิธีเข้ารหัสที่ใช้ 1-4 ไบต์ต่อตัวอักษร ขึ้นกับช่วงของจุดรหัส ตัวอักษรภาษาไทยอยู่ในช่วงที่ต้องใช้ 3 ไบต์ ต่างจาก 'A' ที่ใช้แค่ 1 ไบต์ (เพื่อให้เข้ากันได้กับ ASCII เดิม)

## Time Complexity

การแปลงเลขฐาน (เช่น decimal ↔ binary ↔ hex) มีความซับซ้อนเวลาแบบ **O(log n)** โดย n คือค่าตัวเลข เพราะจำนวนหลักที่ต้องคำนวณแปรผันตามลอการิทึมของค่าตัวเลข (ยิ่งตัวเลขใหญ่ ยิ่งใช้จำนวนหลักมากขึ้นแบบลอการิทึม ไม่ใช่เชิงเส้น)

## Space Complexity

การเก็บตัวเลขในหน่วยความจำใช้พื้นที่คงที่ตามชนิดข้อมูล (เช่น `int32` ใช้ 4 ไบต์เสมอ) แต่การเก็บ**ข้อความ**เป็นแบบแปรผัน — ข้อความภาษาอังกฤษล้วนจะใช้พื้นที่น้อยกว่าข้อความที่มีภาษาไทยหรืออิโมจิปนอยู่ เมื่อเข้ารหัสด้วย UTF-8 (**O(n)** โดย n คือจำนวนตัวอักษร แต่ค่าคงที่ต่อตัวอักษรไม่เท่ากัน)

## แนวทางปฏิบัติที่ดี (Best Practices)

- ใช้ **UTF-8** เป็นค่าเริ่มต้นเสมอเมื่อเก็บ/ส่งข้อความ (มาตรฐานสากลที่นิยมที่สุด รองรับทุกภาษา)
- เมื่อเจอค่าที่ขึ้นต้นด้วย `0x` ให้รู้ทันทีว่านั่นคือเลขฐาน 16 (พบบ่อยใน memory address, color code เช่น `#FF5733`, hash)
- ระวังเรื่อง **encoding mismatch**: เขียนไฟล์ด้วย encoding หนึ่ง แต่เปิดอ่านด้วยอีก encoding หนึ่ง จะทำให้ตัวอักษรเพี้ยน (mojibake) — ควรระบุ encoding ให้ชัดเจนเสมอในโค้ด

## ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

- เข้าใจผิดว่า 1 ตัวอักษร = 1 ไบต์เสมอ — จริงๆ แล้วขึ้นกับภาษาและ encoding (ภาษาไทย/จีน/อิโมจิ ใช้หลายไบต์ต่อตัวอักษรใน UTF-8)
- สับสนระหว่าง **bit** (1 หลักไบนารี) กับ **byte** (8 บิต) — เช่น ความเร็วอินเทอร์เน็ต "100 Mbps" คือ 100 ล้าน**บิต**ต่อวินาที ไม่ใช่ 100 ล้าน**ไบต์** (ต้องหาร 8 เพื่อได้ MB/s)
- ลืมว่าเลขฐาน 16 ที่มีตัวอักษร A-F ไม่ใช่ตัวอักษรภาษาอังกฤษธรรมดา แต่เป็นตัวแทนค่า 10-15

## ข้อคิดสำคัญ (Key Takeaways)

- คอมพิวเตอร์เก็บทุกอย่างเป็นไบนารี (0/1) เพราะฮาร์ดแวร์มีแค่ 2 สถานะไฟฟ้า
- เฮกซาเดซิมัลเป็นเครื่องมือย่อไบนารีให้มนุษย์อ่านง่าย โดย 4 บิต = เลขฐาน 16 หนึ่งหลักพอดี
- ASCII คือมาตรฐานเก่าที่ครอบคลุมแค่ภาษาอังกฤษ (7 บิต, 128 ตัว) ส่วน Unicode คือมาตรฐานใหม่ที่ครอบคลุมทุกภาษาในโลก
- UTF-8 คือวิธีเข้ารหัส Unicode ที่ใช้ 1-4 ไบต์ต่อตัวอักษร แปรผันตามภาษา และเข้ากันได้กับ ASCII เดิม
- ความเข้าใจเรื่องฐานเลขและ encoding เป็นพื้นฐานสำคัญก่อนเรียนเรื่อง memory, data types และ bitwise operation ในบทถัดไป
