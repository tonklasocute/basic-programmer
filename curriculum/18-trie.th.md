# บทที่ 18: Trie

## แนวคิดหลัก (Concept)

Hash Table (บทที่ 15) ค้นหา string ทั้งก้อนได้เร็ว O(1) แต่ทำสิ่งที่พบบ่อยมากในงานจริงไม่ได้ดี: **"หาคำทั้งหมดที่ขึ้นต้นด้วย pre_"** (autocomplete) — ต้องไล่ตรวจทุก key ใน Hash Table ทีละตัว O(n) **Trie (อ่านว่า "ทราย" หรือ "ทรี" — มาจากคำว่า re**trie**val)** คือโครงสร้างข้อมูลที่ถูกออกแบบมาเฉพาะสำหรับข้อมูลประเภท string เพื่อแก้ปัญหานี้โดยเฉพาะ

- **Trie (Prefix Tree)** — Tree พิเศษที่**แต่ละ Node แทน "ตัวอักษรหนึ่งตัว"** ไม่ใช่ "ค่าทั้งก้อน" เหมือน BST/Heap เส้นทางจาก root ไปยัง Node ใดๆ ประกอบกันเป็น**คำนำหน้า (prefix)** ของคำที่เก็บอยู่ในนั้น
- **End-of-word marker** — Node แต่ละตัวมี flag บอกว่า "เส้นทางจาก root ถึงตรงนี้ประกอบกันเป็นคำสมบูรณ์หรือไม่" (เพราะคำหนึ่งอาจเป็น prefix ของอีกคำหนึ่งได้ เช่น "cat" เป็น prefix ของ "catalog")
- **Children เป็น Map ของตัวอักษร** — แต่ละ Node มีลูกได้หลายตัว (ไม่จำกัดแค่ 2 เหมือน Binary Tree) โดยแต่ละกิ่งแทนตัวอักษรถัดไปที่เป็นไปได้

## ทำไมต้องมีสิ่งนี้ (Why it exists)

- **Trie มีไว้แก้ปัญหา "ค้นหาตาม prefix" อย่างมีประสิทธิภาพ**: Hash Table เก็บ string เป็นก้อนเดียว ไม่รู้ความสัมพันธ์ระหว่าง string ที่ขึ้นต้นเหมือนกัน แต่ Trie **แชร์ตัวอักษรที่ขึ้นต้นเหมือนกันไว้ในเส้นทางเดียวกัน** ทำให้หาคำทั้งหมดที่ขึ้นต้นด้วย prefix หนึ่งๆ ได้เร็วมาก โดยแค่เดินไปตาม prefix นั้นครั้งเดียวแล้วไล่ดูกิ่งที่เหลือทั้งหมด
- **ประหยัดพื้นที่เมื่อมีคำจำนวนมากที่ prefix ซ้ำกัน**: ถ้าเก็บ "cat", "car", "card", "care" แยกกันแบบ string เต็มๆ (เช่นใน Hash Table) ตัวอักษร "ca" จะถูกเก็บซ้ำ 4 รอบ แต่ Trie เก็บ "ca" แค่ครั้งเดียวแล้วแตกกิ่งออกไปตามตัวอักษรที่ต่างกัน
- **ความเร็วไม่ขึ้นกับจำนวนคำทั้งหมดในพจนานุกรม แต่ขึ้นกับความยาวของคำที่ค้นหาเท่านั้น**: ค้นหาคำยาว k ตัวอักษรใน Trie ใช้เวลา O(k) เสมอ ไม่ว่า Trie จะมีคำเก็บอยู่กี่ล้านคำก็ตาม — ต่างจาก Hash Table ที่แม้จะเร็ว O(1) แต่ยังต้อง hash ตัวอักษรทั้งหมดของ string นั้นอยู่ดี (และไม่รองรับการค้นหา prefix)

## เปรียบเทียบกับชีวิตจริง (Real-world analogy)

- **Trie** เหมือน **สารบัญพจนานุกรมกระดาษที่แบ่งตามตัวอักษร** — เปิดไปที่ตัว "C" ก่อน (ชั้นที่ 1) แล้วเปิดไปที่ "A" ถัดมา (ชั้นที่ 2, ตอนนี้อยู่ที่ "CA") แล้วเปิดไปที่ "T" (ชั้นที่ 3, ตอนนี้อยู่ที่ "CAT") — ทุกคำที่ขึ้นต้นด้วย "CAT" (เช่น CATALOG, CATCH) จะอยู่ใกล้กันหมดในหน้าถัดจากจุดนี้ ไม่ต้องเปิดพจนานุกรมทั้งเล่มใหม่
- **End-of-word marker** เหมือน **เครื่องหมายดอกจันในพจนานุกรมที่บอกว่า "คำนี้เป็นคำสมบูรณ์"** — "CAT" มีเครื่องหมายดอกจัน (เป็นคำจริง) แต่ "CA" เฉยๆ ไม่มีเครื่องหมาย (เป็นแค่ทางผ่านไปยังคำอื่น ไม่ใช่คำที่สมบูรณ์ในตัวเอง)

## แผนภาพอธิบาย (Visual explanation)

### โครงสร้าง Trie สำหรับคำ "cat", "car", "card", "care", "dog"

```
                         (root)
                        /      \
                      c          d
                      │          │
                      a          o
                      │          │
                      │          g*        ← * = end-of-word ("dog" สมบูรณ์)
              ┌───────┴───────┐
              t*               r
      (end: "cat")             │
                        ┌───────┼───────┐
                        (r ตัวนี้        e*
                         ยังไม่จบคำ)   (end: "care")
                              │
                              d*
                        (end: "card")

หมายเหตุ: เส้นทาง root -> c -> a -> r คือ "car" แต่ node "r" ไม่มี * (ไม่ marked end-of-word)
         เพราะในตัวอย่างนี้ "car" ก็เป็นคำสมบูรณ์ด้วย ในทางปฏิบัติควร mark * ที่ node "r" ด้วย
```

### การค้นหาคำ "care" ทีละตัวอักษร

```
เริ่มที่ root
  ตัว 'c' -> มีกิ่งนี้หรือไม่? มี -> เดินไป Node 'c'
  ตัว 'a' -> มีกิ่งนี้หรือไม่? มี -> เดินไป Node 'a'
  ตัว 'r' -> มีกิ่งนี้หรือไม่? มี -> เดินไป Node 'r'
  ตัว 'e' -> มีกิ่งนี้หรือไม่? มี -> เดินไป Node 'e'
  จบคำแล้ว -> ตรวจ end-of-word marker ที่ Node 'e' -> True -> "care" มีอยู่จริง ✓

ใช้เวลาเดินแค่ 4 ก้าว (เท่ากับความยาวคำ "care") ไม่ว่า Trie จะมีคำอื่นอีกกี่ล้านคำก็ตาม
```

### Autocomplete — หาคำทั้งหมดที่ขึ้นต้นด้วย "ca"

```
1. เดินตาม prefix "ca" ไปจนถึง Node 'a' (ใช้ 2 ก้าว)
2. จาก Node 'a' ทำ DFS/Traversal (บทที่ 23) ไล่ดูทุกกิ่งที่เหลือ
   -> เจอ "t*" (cat), เจอ "r" -> "d*" (card) และ "e*" (care)
3. ผลลัพธ์: ["cat", "card", "care"]  (ทุกคำที่ขึ้นต้นด้วย "ca")
```

## ตัวอย่างโค้ด (Code example)

```python
class TrieNode:
    def __init__(self):
        self.children = {}          # dict: ตัวอักษร -> TrieNode ถัดไป (ใช้ Hash Table จากบทที่ 15!)
        self.is_end_of_word = False  # end-of-word marker

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        current = self.root
        for char in word:
            if char not in current.children:
                current.children[char] = TrieNode()   # สร้างกิ่งใหม่ถ้ายังไม่มี
            current = current.children[char]            # เดินตามกิ่งไปเรื่อยๆ
        current.is_end_of_word = True                    # จบคำ -> mark ไว้

    def search(self, word):                              # ค้นหาคำแบบสมบูรณ์
        node = self._find_node(word)
        return node is not None and node.is_end_of_word

    def starts_with(self, prefix):                       # ตรวจว่ามีคำที่ขึ้นต้นด้วย prefix นี้หรือไม่
        return self._find_node(prefix) is not None

    def _find_node(self, prefix):
        current = self.root
        for char in prefix:
            if char not in current.children:
                return None                                # เดินไปไม่ถึง -> ไม่มี prefix นี้แน่นอน
            current = current.children[char]
        return current

trie = Trie()
for word in ["cat", "car", "card", "care", "dog"]:
    trie.insert(word)

print(trie.search("car"))          # True
print(trie.search("ca"))           # False ("ca" ไม่ใช่คำสมบูรณ์ แค่เป็น prefix)
print(trie.starts_with("ca"))      # True (มีคำที่ขึ้นต้นด้วย "ca" อยู่)
print(trie.starts_with("xyz"))     # False
```

## ทำงานทีละขั้นตอน (Step-by-step execution)

1. `trie.insert("car")` — เริ่มที่ `root` ไล่ทีละตัวอักษร `'c'` → ไม่มีใน `root.children` → สร้าง `TrieNode()` ใหม่ผูกกับ key `'c'` → เดินเข้าไป → `'a'` → สร้างใหม่อีก (ยังไม่มี เพราะเพิ่ง insert คำแรก) → เดินเข้าไป → `'r'` → สร้างใหม่ → เดินเข้าไป → ครบตัวอักษรแล้ว → ตั้ง `current.is_end_of_word = True` ที่ Node 'r' นี้
2. `trie.insert("card")` (คำถัดมา) — เดิน `'c'` → **มีอยู่แล้ว** (จาก "car") → ใช้กิ่งเดิม → `'a'` → มีอยู่แล้ว → ใช้กิ่งเดิม → `'r'` → มีอยู่แล้ว → ใช้กิ่งเดิม → `'d'` → **ยังไม่มี** → สร้างใหม่ → ตั้ง end-of-word ที่ Node 'd' — สังเกตว่าตัวอักษร "car" ทั้งสามตัวถูก**ใช้ซ้ำ** ไม่ต้องสร้างใหม่ นี่คือการประหยัดพื้นที่ที่กล่าวถึงข้างต้น
3. `trie.search("ca")` — เดินตาม `'c'` → `'a'` ได้สำเร็จ (Node มีอยู่จริง) แต่ **`current.is_end_of_word` ที่ Node 'a' เป็น `False`** (เพราะไม่มีคำไหนที่เป็น "ca" พอดีถูก insert ไว้) จึงคืนค่า `False` — ต่างจาก `starts_with("ca")` ที่แค่เช็คว่า**เดินไปถึง Node ได้หรือไม่** โดยไม่สนใจ end-of-word marker เลย

## Time Complexity

| Operation | Complexity | เหตุผล |
|---|---|---|
| Insert คำความยาว k | O(k) | เดินตาม/สร้าง Node ทีละตัวอักษร ไม่ขึ้นกับจำนวนคำอื่นใน Trie เลย |
| Search คำความยาว k | O(k) | เดินตาม Node ทีละตัวอักษรจนครบหรือจนเจอทางตัน |
| starts_with (prefix) ความยาว k | O(k) | เหมือน search แต่ไม่เช็ค end-of-word |
| Autocomplete (หาทุกคำที่ขึ้นต้นด้วย prefix) | O(k + m) | k = เดินไปหา prefix, m = จำนวน Node ทั้งหมดที่ต้องไล่ต่อจากนั้น (ขึ้นกับจำนวนคำที่ match) |

จุดสำคัญ: **ความเร็วของ Trie ขึ้นกับความยาวคำที่ค้นหา (k) เท่านั้น ไม่ขึ้นกับจำนวนคำทั้งหมดที่เก็บอยู่ (n)** ต่างจาก Hash Table ที่แม้จะเร็ว O(1) โดยเฉลี่ย แต่ก็ยังต้อง hash ตัวอักษรทั้งหมดอยู่ดี และไม่รองรับ prefix search เลย

## Space Complexity

Trie ใช้พื้นที่ตามจำนวน Node ทั้งหมด ซึ่งในกรณีแย่ที่สุด (ไม่มี prefix ซ้ำกันเลย) อาจเป็น **O(total characters)** ของทุกคำรวมกัน แต่ในทางปฏิบัติที่มักมี prefix ซ้ำกันมาก (เช่น พจนานุกรมภาษาอังกฤษ) จะ**ประหยัดกว่า**การเก็บทุกคำแยกกันแบบเต็มใน Hash Table อย่างมีนัยสำคัญ

## ข้อดี (Advantages)

- ค้นหา prefix/autocomplete ได้เร็วมาก O(k) โดยไม่ขึ้นกับจำนวนคำทั้งหมด
- ประหยัดพื้นที่เมื่อมีคำจำนวนมากที่ prefix ซ้ำกัน (แชร์เส้นทางร่วมกัน)
- รองรับการ "เดินไล่" คำทั้งหมดที่ตรงเงื่อนไข prefix ได้อย่างเป็นธรรมชาติ (ต่างจาก Hash Table ที่ต้องไล่ทุก key)

## ข้อเสีย (Disadvantages)

- ใช้หน่วยความจำมากกว่า Hash Table ถ้าคำส่วนใหญ่ไม่มี prefix ซ้ำกันเลย (แต่ละ Node มี overhead ของ dict/map ภายใน)
- ใช้ได้เฉพาะกับข้อมูลที่เป็นลำดับ (sequence) เช่น string เท่านั้น ไม่เหมาะกับข้อมูลทั่วไปแบบ Hash Table
- Implement ซับซ้อนกว่า Hash Table เล็กน้อย (ต้องจัดการ TrieNode และ end-of-word marker เอง)

## การใช้งานจริง (Real-world usage)

- **Autocomplete/Search suggestion** ในเสิร์ชเอนจิน แอปพิมพ์ข้อความ (เช่น คำแนะนำขณะพิมพ์ใน Google Search)
- **Spell checker** — ตรวจสอบว่าคำที่พิมพ์มีอยู่ในพจนานุกรมหรือไม่ พร้อมแนะนำคำใกล้เคียง
- **IP Routing (Longest Prefix Matching)** — เราเตอร์เครือข่ายใช้โครงสร้างคล้าย Trie หาเส้นทางที่ตรงกับ prefix ของ IP address ยาวที่สุด
- **T9 predictive text** บนมือถือรุ่นเก่า และระบบแนะนำคำในแป้นพิมพ์มือถือปัจจุบัน

## แนวทางปฏิบัติที่ดี (Best Practices)

- ใช้ Trie เมื่อโจทย์เกี่ยวข้องกับ**การค้นหาตาม prefix** หรือ autocomplete โดยเฉพาะ — ถ้าแค่ต้องการค้นหาคำแบบสมบูรณ์เท่านั้น (ไม่สนใจ prefix) Hash Table เร็วกว่าและง่ายกว่า
- ใช้ dictionary/hash map เป็น `children` ของแต่ละ Node (ตามตัวอย่าง) แทน array คงที่ 26 ช่อง (สำหรับ a-z) เมื่อ character set มีขนาดใหญ่หรือไม่แน่นอน (เช่น รองรับภาษาไทยหรือ Unicode ด้วย) เพื่อประหยัดพื้นที่
- เมื่อ implement autocomplete ให้แยกขั้นตอน "เดินไปหา prefix node" กับ "ไล่เก็บคำทั้งหมดจากจุดนั้น" ออกจากกันชัดเจน (ตามตัวอย่างในแผนภาพ)

## ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

- ลืมตั้งค่า `is_end_of_word` ทำให้ `search("car")` คืนค่า False แม้จะ insert "car" ไปแล้ว (สับสนระหว่าง "เดินไปถึง Node ได้" กับ "เป็นคำสมบูรณ์")
- สับสนระหว่าง `search()` (ต้องเป็นคำสมบูรณ์) กับ `starts_with()` (แค่เป็น prefix ก็พอ) — ใช้ผิดฟังก์ชันทำให้ผลลัพธ์ผิดพลาด
- ใช้ Trie ทั้งที่โจทย์ไม่เกี่ยวกับ prefix เลย ทำให้เสียพื้นที่หน่วยความจำโดยไม่จำเป็นเมื่อเทียบกับ Hash Table ที่ง่ายกว่า
- ไม่จัดการกรณีคำซ้ำ (insert คำเดิมสองครั้ง) อาจทำให้นับจำนวนคำผิดถ้ามีการนับความถี่ร่วมด้วย

## Mini Project

**"ระบบ Autocomplete ค้นหาสินค้า (Product Search Autocomplete)"**: เขียนโปรแกรมที่:
1. โหลดรายชื่อสินค้าจำนวนมาก (เช่น 10,000 ชื่อสินค้าจากไฟล์) เข้า Trie
2. รับ input จากผู้ใช้ทีละตัวอักษร จำลองการพิมพ์ในช่องค้นหา แล้วแสดงคำแนะนำ (suggestion) ที่ขึ้นต้นด้วยข้อความที่พิมพ์อยู่แบบ real-time (สูงสุด 5 รายการ)
3. เปรียบเทียบเวลาค้นหา prefix เดียวกันระหว่าง Trie กับการไล่ตรวจ list ของชื่อสินค้าทั้งหมดด้วย `startswith()` ธรรมดา (linear scan) เมื่อข้อมูลมีจำนวนมากขึ้นเรื่อยๆ เพื่อพิสูจน์ข้อได้เปรียบด้าน time complexity ที่เรียนมา

## ข้อคิดสำคัญ (Key Takeaways)

- Trie คือ Tree ที่แต่ละ Node แทนตัวอักษรหนึ่งตัว ใช้เก็บและค้นหาข้อมูลประเภท string โดยเฉพาะ โดยแชร์ prefix ที่ซ้ำกันไว้ในเส้นทางเดียวกัน
- ค้นหา/แทรกคำความยาว k ใช้เวลา O(k) เสมอ ไม่ขึ้นกับจำนวนคำทั้งหมดที่เก็บอยู่ ต่างจาก Hash Table
- Trie ทำสิ่งที่ Hash Table ทำไม่ได้ดี คือค้นหาตาม prefix/autocomplete ได้อย่างมีประสิทธิภาพ
- ต้องมี end-of-word marker เพื่อแยกแยะระหว่าง "เป็น prefix ที่มีอยู่" กับ "เป็นคำสมบูรณ์จริงๆ"
- Trie แลกพื้นที่หน่วยความจำที่มากขึ้นเล็กน้อย (ถ้า prefix ไม่ซ้ำกันมาก) เพื่อความเร็วในการค้นหาตาม prefix
- บทถัดไปจะเรียน Graph ซึ่งเป็นโครงสร้างข้อมูลที่ทั่วไปที่สุดในบรรดา Data Structures ทั้งหมด — Tree ทุกชนิดที่เรียนมา (BST, AVL, Heap, Trie) จริงๆ แล้วเป็นกรณีพิเศษของ Graph นั่นเอง
