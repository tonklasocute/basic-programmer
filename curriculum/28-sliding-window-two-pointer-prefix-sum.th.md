# บทที่ 28: Sliding Window, Two Pointer, Prefix Sum

## แนวคิดหลัก (Concept)

บทที่ผ่านมา (D&C, DP, Greedy, Backtracking) ล้วนเป็นเทคนิคที่ทรงพลังแต่ค่อนข้าง "หนัก" — บทนี้แนะนำสามเทคนิคที่**เบากว่ามาก** ใช้แก้ปัญหาเกี่ยวกับ array/string ที่พบบ่อยที่สุดในการสัมภาษณ์งานจริง โดยทั้งสามเทคนิคมีจุดร่วมกันคือ **ลดจำนวนรอบ loop ที่ซ้อนกัน (nested loop) จาก O(n²) เหลือ O(n)** ด้วยการใช้ข้อมูลที่คำนวณไปแล้วให้เป็นประโยชน์ แทนที่จะคำนวณซ้ำใหม่ทุกครั้ง

- **Two Pointer (สองตัวชี้)** — ใช้ตัวแปร index สองตัวเดินไปพร้อมกันในทิศทางเดียวกันหรือตรงข้ามกัน แทนการใช้ nested loop เทียบทุกคู่ที่เป็นไปได้
- **Sliding Window (หน้าต่างเลื่อน)** — รักษาช่วงข้อมูลต่อเนื่อง (window) ที่ขยับขอบซ้าย/ขวาไปเรื่อยๆ แทนการคำนวณช่วงย่อยใหม่ทั้งหมดทุกครั้ง — เป็นกรณีพิเศษของ Two Pointer ที่ทั้งสอง pointer เคลื่อนไปทิศทางเดียวกันเสมอ
- **Prefix Sum (ผลรวมสะสม)** — สร้างอาร์เรย์เสริมที่เก็บ "ผลรวมตั้งแต่ต้นจนถึงตำแหน่งนั้น" ไว้ล่วงหน้า ทำให้หาผลรวมของช่วงใดๆ ได้ใน O(1) แทนที่จะบวกใหม่ทุกครั้ง

## ทำไมต้องมีสิ่งนี้ (Why it exists)

- **มีไว้กำจัด nested loop ที่ไม่จำเป็นซึ่งเป็นสาเหตุอันดับหนึ่งของ Brute Force O(n²)**: ปัญหาจำนวนมาก (หาผลรวมย่อยที่เท่ากับเป้าหมาย, หาคู่ที่รวมกันได้ค่าที่กำหนด, หา substring ที่ยาวที่สุดตามเงื่อนไข) ดูเหมือนต้องเทียบทุกคู่/ทุกช่วงที่เป็นไปได้ตรงๆ แต่แท้จริงมีวิธีลดเหลือ O(n) ได้เสมอถ้าข้อมูลมีคุณสมบัติบางอย่าง (เช่น เรียงแล้ว หรือเป็นค่าบวกทั้งหมด)
- **Two Pointer ใช้ประโยชน์จากข้อมูลที่เรียงแล้ว**: เมื่อข้อมูลเรียงลำดับ (เชื่อมโยงกับ Binary Search บทที่ 22) การเลื่อน pointer เข้าหากันสามารถตัดทิ้งความเป็นไปได้จำนวนมากได้ในแต่ละก้าว เหมือนหลักการเดียวกับ Binary Search แต่ประยุกต์กับการหาคู่แทนการหาค่าเดียว
- **Prefix Sum มีไว้ตอบคำถาม "ผลรวมของช่วง [i, j]" ซ้ำๆ กันหลายครั้งอย่างมีประสิทธิภาพ**: ถ้าต้องตอบคำถามแบบนี้ q ครั้งบน array ขนาด n การบวกใหม่ทุกครั้งเสีย O(n×q) แต่เตรียม Prefix Sum ล่วงหน้าครั้งเดียว O(n) แล้วตอบแต่ละคำถามด้วย O(1) ทำให้รวมเป็น O(n+q) เร็วกว่ามากเมื่อ q มีค่ามาก

## เปรียบเทียบกับชีวิตจริง (Real-world analogy)

- **Two Pointer** เหมือน **สองคนเดินหาจุดนัดพบจากปลายถนนสองฝั่งเข้าหากัน** — แทนที่คนคนเดียวจะเดินสำรวจทั้งถนนไปมาซ้ำๆ (nested loop) สองคนเดินเข้าหากันพร้อมกัน เจอกันเร็วกว่ามาก
- **Sliding Window** เหมือน **การเลื่อนกรอบดูรูปถ่ายทีละภาพต่อเนื่องบนฟิล์ม** — กรอบมีขนาดคงที่หรือปรับได้ เลื่อนไปทีละภาพโดยไม่ต้องหยิบฟิล์มทั้งม้วนมาดูใหม่ทุกครั้ง แค่ขยับกรอบออกจากภาพเก่าและเข้าสู่ภาพใหม่
- **Prefix Sum** เหมือน **ใบแจ้งยอดบัญชีธนาคารที่โชว์ "ยอดคงเหลือสะสม" ทุกวัน** — ถ้าอยากรู้ว่าใช้เงินไปเท่าไหร่ระหว่างวันที่ 5 ถึงวันที่ 20 แค่เอายอดคงเหลือวันที่ 20 ลบยอดคงเหลือวันที่ 4 ก็ได้คำตอบทันที ไม่ต้องรวมรายจ่ายทีละวันใหม่ทั้งหมด

## แผนภาพอธิบาย (Visual explanation)

### Two Pointer — หาคู่ตัวเลขที่รวมกันได้เป้าหมาย (ข้อมูลเรียงแล้ว)

```
arr = [2, 4, 7, 9, 11, 15]     target = 16

left=0(2)                                    right=5(15)
 2 + 15 = 17 > 16  -> มากไป -> เลื่อน right เข้ามา (ค่ามากไปมักลด ไม่มัวเลื่อน left)

left=0(2)                            right=4(11)
 2 + 11 = 13 < 16  -> น้อยไป -> เลื่อน left ออกไป (ค่าน้อยไปมักเพิ่ม)

     left=1(4)                       right=4(11)
 4 + 11 = 15 < 16  -> น้อยไป -> เลื่อน left

         left=2(7)                   right=4(11)
 7 + 11 = 18 > 16  -> มากไป -> เลื่อน right เข้ามา

         left=2(7)              right=3(9)
 7 + 9 = 16 = 16 ✓ เจอคู่ที่ต้องการ!

ใช้ไปแค่ไม่กี่รอบ เทียบกับ Brute Force ที่ต้องเทียบทุกคู่ O(n²)
```

### Sliding Window — หา Subarray ยาวสุดที่ผลรวมไม่เกิน K (K=8)

```
arr = [2, 1, 3, 4, 1, 2]     K=8

window: [2]              sum=2 <=8  ขยายขวาต่อ         ขนาด=1
window: [2,1]             sum=3 <=8  ขยายขวาต่อ         ขนาด=2
window: [2,1,3]           sum=6 <=8  ขยายขวาต่อ         ขนาด=3
window: [2,1,3,4]         sum=10 >8  หดซ้าย! ลบ 2      -> sum=8
window: [1,3,4]           sum=8 <=8  ขยายขวาต่อ         ขนาด=3
window: [1,3,4,1]         sum=9 >8  หดซ้าย! ลบ 1        -> sum=8
window: [3,4,1]           sum=8 <=8  ขยายขวาต่อ         ขนาด=3
window: [3,4,1,2]         sum=10 >8  หดซ้าย! ลบ 3       -> sum=7
window: [4,1,2]           sum=7 <=8                     ขนาด=3

ขนาด window สูงสุดที่เจอตลอดทาง = 3   (คำตอบ)
สังเกต: ขอบซ้ายและขวาเดินไปทางเดียวกันเสมอ ไม่มีทางถอยหลัง -> รวมกันเดิน O(n) ครั้งเท่านั้น ไม่ใช่ O(n²)
```

### Prefix Sum — ตอบคำถาม "ผลรวมช่วง [i,j]" หลายครั้งแบบ O(1)

```
arr = [3, 1, 4, 1, 5, 9, 2]     index:  0  1  2  3  4  5  6

prefix[0] = 0                          (ผลรวมก่อนเริ่ม = 0 เสมอ)
prefix[1] = prefix[0] + arr[0] = 3
prefix[2] = prefix[1] + arr[1] = 4
prefix[3] = prefix[2] + arr[2] = 8
prefix[4] = prefix[3] + arr[3] = 9
prefix[5] = prefix[4] + arr[4] = 14
prefix[6] = prefix[5] + arr[5] = 23
prefix[7] = prefix[6] + arr[6] = 25

prefix = [0, 3, 4, 8, 9, 14, 23, 25]

คำถาม: ผลรวมของ arr[2..5] (index 2 ถึง 5, ค่า 4,1,5,9) คือเท่าไหร่?
ตอบ: prefix[6] - prefix[2] = 23 - 4 = 19    ✓ (4+1+5+9 = 19 ตรง!)
ไม่ต้องบวกทีละตัวใหม่เลย ใช้แค่การลบ O(1)
```

## ตัวอย่างโค้ด (Code example)

```python
# ===== Two Pointer: หาคู่ที่รวมกันได้ target (ข้อมูลต้องเรียงแล้ว) =====
def two_sum_sorted(arr, target):
    left, right = 0, len(arr) - 1
    while left < right:
        current_sum = arr[left] + arr[right]
        if current_sum == target:
            return (left, right)
        elif current_sum < target:
            left += 1                  # ผลรวมน้อยไป -> เพิ่มค่า -> เลื่อน left เข้าหาตัวที่มากขึ้น
        else:
            right -= 1                 # ผลรวมมากไป -> ลดค่า -> เลื่อน right เข้าหาตัวที่น้อยลง
    return None                          # ไม่มีคู่ไหนรวมกันได้ target

# ===== Sliding Window (แบบขนาดแปรผัน): Subarray ยาวสุดที่ผลรวมไม่เกิน K =====
def longest_subarray_max_sum(arr, k):
    left = 0
    current_sum = 0
    max_length = 0
    for right in range(len(arr)):          # ขอบขวาเดินหน้าทีละก้าวเสมอ
        current_sum += arr[right]            # ขยาย window ทางขวา
        while current_sum > k:                # หด window ทางซ้ายจนกว่าจะกลับมา valid
            current_sum -= arr[left]
            left += 1
        max_length = max(max_length, right - left + 1)
    return max_length

# ===== Prefix Sum: เตรียมล่วงหน้า O(n) แล้วตอบคำถามช่วงแบบ O(1) =====
def build_prefix_sum(arr):
    prefix = [0] * (len(arr) + 1)
    for i in range(len(arr)):
        prefix[i + 1] = prefix[i] + arr[i]     # prefix[i+1] = ผลรวม arr[0..i]
    return prefix

def range_sum(prefix, i, j):                    # ผลรวมของ arr[i..j] (inclusive ทั้งสองด้าน)
    return prefix[j + 1] - prefix[i]

print(two_sum_sorted([2, 4, 7, 9, 11, 15], 16))         # (2, 3) -> arr[2]+arr[3] = 7+9 = 16
print(longest_subarray_max_sum([2, 1, 3, 4, 1, 2], 8))    # 3
prefix = build_prefix_sum([3, 1, 4, 1, 5, 9, 2])
print(range_sum(prefix, 2, 5))                             # 19
```

## ทำงานทีละขั้นตอน (Step-by-step execution)

1. `two_sum_sorted` — ใช้ประโยชน์จากการที่ข้อมูล**เรียงแล้ว**: ถ้าผลรวมปัจจุบันน้อยกว่า target แปลว่าต้องการค่าที่มากขึ้น การเลื่อน `left` ไปทางขวา (ไปหาค่าที่มากกว่า เพราะเรียงแล้ว) เป็นทางเดียวที่ทำให้ผลรวมเพิ่มขึ้นได้ ในทางกลับกันถ้าผลรวมมากไป เลื่อน `right` มาทางซ้ายเพื่อลดค่า — **ทุกก้าวตัดทิ้งความเป็นไปได้ที่ไม่ใช่คำตอบทันที** โดยไม่ต้องเทียบคู่นั้นซ้ำอีก (ต่างจาก Brute Force ที่เทียบทุกคู่จริงๆ)
2. `longest_subarray_max_sum` — ใช้ loop เดียว (`for right`) ควบคุมขอบขวาที่เดินหน้าเสมอ ส่วนขอบซ้าย (`left`) เดินหน้าเฉพาะตอนที่ window ผิดเงื่อนไข (`current_sum > k`) ผ่าน `while` loop ข้างใน — ทั้ง `left` และ `right` **รวมกันแล้วเดินไม่เกิน n ก้าวตลอดทั้งฟังก์ชัน** (แต่ละตัวเดินไปข้างหน้าอย่างเดียว ไม่มีถอยหลัง) ทำให้ time complexity เป็น O(n) แม้จะมี loop ซ้อนกัน 2 ชั้นก็ตาม — นี่คือจุดที่มือใหม่มักเข้าใจผิดว่าเป็น O(n²) เพราะเห็น nested loop แต่จริงๆ ไม่ใช่
3. `build_prefix_sum` — สร้างอาร์เรย์ที่มีขนาด `len(arr)+1` โดยเจตนา (ไม่ใช่ `len(arr)`) และกำหนด `prefix[0] = 0` เสมอ เพื่อให้สูตร `range_sum` ทำงานถูกต้องแม้ `i=0` (ถ้าไม่มี `prefix[0]=0` เป็นฐาน จะต้องเขียนเงื่อนไขพิเศษแยกกรณี `i=0` ออกจากกรณีอื่น)
4. `range_sum(prefix, i, j)` — สูตร `prefix[j+1] - prefix[i]` ทำงานเพราะ `prefix[j+1]` คือผลรวมทั้งหมดตั้งแต่ `arr[0]` ถึง `arr[j]` และ `prefix[i]` คือผลรวมตั้งแต่ `arr[0]` ถึง `arr[i-1]` (ไม่รวม `arr[i]`) การลบสองค่านี้จึงเหลือพอดีแค่ผลรวมของ `arr[i]` ถึง `arr[j]` เท่านั้น

## Time Complexity

| Technique | Brute Force | ด้วยเทคนิคนี้ |
|---|---|---|
| Two Pointer (หาคู่ในข้อมูลเรียงแล้ว) | O(n²) (เทียบทุกคู่) | **O(n)** |
| Sliding Window (หา subarray ตามเงื่อนไข) | O(n²) หรือ O(n³) (ลองทุกช่วงย่อย) | **O(n)** |
| Prefix Sum (ตอบคำถามผลรวมช่วง q ครั้ง) | O(n × q) (บวกใหม่ทุกครั้ง) | **O(n + q)** (เตรียม O(n) ครั้งเดียว + ตอบ O(1) ต่อคำถาม) |

## Space Complexity

- Two Pointer: **O(1)** — ใช้แค่ตัวแปร `left`, `right` คงที่ ไม่สร้างข้อมูลใหม่
- Sliding Window: **O(1)** — เก็บแค่ `current_sum` และขอบเขต window ไม่ต้องเก็บ window ทั้งหมดเป็น array แยก
- Prefix Sum: **O(n)** — ต้องสร้างอาร์เรย์เสริมขนาด n+1 เพื่อแลกกับการตอบคำถามที่เร็วขึ้นมาก (trade-off พื้นที่แลกเวลา คล้ายกับที่เห็นใน Merge Sort บทที่ 21 และ Memoization บทที่ 25)

## แนวทางปฏิบัติที่ดี (Best Practices)

- ใช้ Two Pointer เมื่อข้อมูล**เรียงลำดับแล้ว**หรือ sort ได้ก่อนใช้งาน (การ sort เสีย O(n log n) แต่ยังคุ้มกว่า Brute Force O(n²) โดยรวม) — ถ้าข้อมูลไม่เรียงและ sort ไม่ได้ (เช่น ต้องรักษาลำดับเดิม) ให้พิจารณา Hash Set/Map แทน
- ใช้ Sliding Window เฉพาะเมื่อข้อมูลเป็น**ค่าที่ไม่ติดลบ** (ผลรวมเพิ่มขึ้นเสมอเมื่อขยาย window) ถ้ามีค่าติดลบปนอยู่ เงื่อนไข "หด window เมื่อเกิน" อาจใช้ไม่ได้ผล ต้องพิจารณา Prefix Sum + Hash Map แทน
- สร้าง Prefix Sum ล่วงหน้าเสมอเมื่อรู้ว่าต้องตอบคำถาม "ผลรวมของช่วง" หลายครั้งบนข้อมูลเดิมที่ไม่เปลี่ยนแปลง แทนที่จะคำนวณใหม่ทุกครั้งที่มีคำถาม

## ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

- ใช้ Two Pointer กับข้อมูลที่**ยังไม่ได้เรียงลำดับ** ได้ผลลัพธ์ผิดโดยไม่มี error แจ้งเตือน (เหมือนปัญหาเดียวกับ Binary Search ในบทที่ 22)
- เห็น nested loop (`for` ข้างนอก + `while` ข้างใน) แล้วรีบสรุปว่าเป็น O(n²) ทันทีโดยไม่วิเคราะห์ว่า pointer แต่ละตัวเดินหน้าทางเดียวรวมกันไม่เกิน n ครั้งจริงๆ (เหมือนใน `longest_subarray_max_sum`) — ทำให้ประเมิน complexity ผิดพลาด
- ใช้ Sliding Window กับข้อมูลที่มีค่าติดลบ โดยไม่ตระหนักว่าเงื่อนไขการหด window อาจใช้ไม่ได้ผลถูกต้อง (ผลรวมอาจไม่ได้เพิ่มขึ้นเสมอเมื่อขยาย window ถ้ามีค่าติดลบ)
- ลืมสร้าง Prefix Sum ขนาด `n+1` (สร้างแค่ `n` แทน) ทำให้เกิด index error หรือต้องเขียนเงื่อนไขพิเศษแยกกรณี `i=0` ที่ไม่จำเป็น
- คำนวณ `range_sum(prefix, i, j)` ผิดสูตร (เช่น ใช้ `prefix[j] - prefix[i]` แทน `prefix[j+1] - prefix[i]`) ทำให้ขาดหรือเกิน `arr[j]` ไปหนึ่งตัว

4. Sliding Window ต่างจาก Two Pointer อย่างไร ทำไมถึงถือว่า Sliding Window เป็นกรณีพิเศษของ Two Pointer
5. ถ้าข้อมูลมีค่าติดลบปนอยู่ จะปรับ Prefix Sum หรือ Sliding Window อย่างไรให้ยังใช้งานได้ถูกต้อง

## Mini Project

**"เครื่องมือวิเคราะห์ข้อมูลหุ้นรายวัน (Stock Price Analyzer)"**: เขียนโปรแกรมที่:
1. รับข้อมูลราคาหุ้นรายวันเป็น array ใช้ Prefix Sum สร้างระบบตอบคำถาม "ผลรวมราคาระหว่างวันที่ i ถึง j" และ "ราคาเฉลี่ยในช่วงที่กำหนด" แบบ O(1) ต่อคำถาม
2. ใช้ Sliding Window หา **ช่วง k วันติดต่อกันที่มีผลรวมราคาสูงสุด** (fixed-size window)
3. ใช้ Two Pointer หา **สองวันที่ราคาห่างกันมากที่สุดโดยวันขายต้องอยู่หลังวันซื้อ** (คล้ายปัญหา Best Time to Buy and Sell Stock)
4. เปรียบเทียบเวลาทำงานจริงระหว่างวิธี Brute Force (nested loop ธรรมดา) กับวิธีที่ใช้เทคนิคในบทนี้ เมื่อข้อมูลมีขนาด 1,000, 10,000, 100,000 วัน แสดงผลเป็นตาราง

## ข้อคิดสำคัญ (Key Takeaways)

- Two Pointer, Sliding Window, และ Prefix Sum ล้วนเป็นเทคนิคที่ลด nested loop O(n²) เหลือ O(n) หรือ O(n+q) โดยใช้ประโยชน์จากคุณสมบัติของข้อมูล (เรียงแล้ว, ไม่ติดลบ, ต้องการคำนวณซ้ำ)
- Two Pointer ใช้ได้ผลเมื่อข้อมูลเรียงแล้ว เลื่อน pointer เข้าหากันเพื่อตัดทิ้งความเป็นไปได้ทีละก้าว
- Sliding Window เป็นกรณีพิเศษของ Two Pointer ที่ทั้งสอง pointer เดินไปทิศทางเดียวกันเสมอ เหมาะกับปัญหาช่วงข้อมูลต่อเนื่องที่มีค่าไม่ติดลบ
- Prefix Sum แลกพื้นที่ O(n) เพื่อให้ตอบคำถามผลรวมช่วงได้ O(1) ต่อคำถาม เหมาะเมื่อต้องตอบคำถามแบบเดิมซ้ำหลายครั้งบนข้อมูลที่ไม่เปลี่ยนแปลง
- ทั้งสามเทคนิคเป็นทักษะพื้นฐานที่พบบ่อยที่สุดในการสัมภาษณ์งานสายเทคโนโลยี เพราะมักปรากฏในปัญหา array/string ระดับ easy-medium ที่ดูซับซ้อนแต่แก้ได้อย่างสง่างามด้วยเทคนิคเหล่านี้
- บทถัดไปจะเรียน Union Find ซึ่งเป็นโครงสร้างข้อมูล/เทคนิคสุดท้ายของ Part 5 เหมาะกับปัญหาการจัดกลุ่มและตรวจสอบการเชื่อมต่อ ซึ่งจะเชื่อมโยงกลับไปที่ Graph (บทที่ 19) และ Kruskal's Algorithm ที่กล่าวถึงในบทที่แล้ว
