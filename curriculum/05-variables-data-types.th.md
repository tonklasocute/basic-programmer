# บทที่ 5: Variables, Data Types, Constants

## แนวคิดหลัก (Concept)

จากบทที่ 3 เรารู้แล้วว่าโปรแกรมมี Stack และ Heap ไว้เก็บข้อมูลขณะทำงาน แต่ในระดับโค้ดที่เราเขียนจริง เราไม่ได้ยุ่งกับ address ของหน่วยความจำโดยตรง — เราใช้ **ตัวแปร (Variable)** เป็นชื่อที่ผูกไว้กับตำแหน่งข้อมูลนั้น

- **Variable (ตัวแปร)** — ชื่อที่ตั้งขึ้นเพื่ออ้างอิงถึงค่าที่เก็บอยู่ในหน่วยความจำ ค่านั้นสามารถเปลี่ยนแปลงได้ระหว่างที่โปรแกรมทำงาน
- **Data Type (ชนิดข้อมูล)** — บอกว่าค่าที่เก็บในตัวแปรนั้นคือข้อมูลแบบไหน (ตัวเลขจำนวนเต็ม, ทศนิยม, ข้อความ, จริง/เท็จ ฯลฯ) ซึ่งกำหนดว่าใช้พื้นที่หน่วยความจำเท่าไหร่ และทำ operation อะไรกับมันได้บ้าง
- **Constant (ค่าคงที่)** — เหมือนตัวแปร แต่ **ห้ามเปลี่ยนค่าหลังกำหนดครั้งแรก** ใช้เพื่อบอกเจตนาว่าค่านี้ไม่ควรถูกแก้ไข และป้องกัน bug จากการเผลอเปลี่ยนค่าที่ไม่ควรเปลี่ยน

## ทำไมต้องมีสิ่งนี้ (Why it exists)

- **ตัวแปรมีไว้แทนที่ raw memory address**: ถ้าต้องเขียนโปรแกรมโดยอ้างอิง memory address ตรงๆ (เช่น `0x7ffee23a`) จะอ่านยากและผิดพลาดง่ายมาก ตัวแปรทำให้โค้ดอ่านเข้าใจง่าย (`age`, `username`) แทนที่จะเป็นตัวเลขที่อยู่
- **ชนิดข้อมูลมีไว้เพื่อความปลอดภัยและประสิทธิภาพ**: คอมไพเลอร์/interpreter ต้องรู้ว่าจะจองพื้นที่เท่าไหร่ (int ใช้ 4 ไบต์ แต่ string ยาวไม่แน่นอน) และป้องกันการทำ operation ที่ไม่สมเหตุสมผล (เช่น เอาข้อความไปหารด้วยตัวเลข)
- **Constant มีไว้เพื่อสื่อสารเจตนาและป้องกันบั๊ก**: ถ้าค่าบางอย่าง (เช่น ค่า PI, อัตราภาษี) ไม่ควรถูกเปลี่ยนระหว่างโปรแกรมทำงาน การประกาศเป็น constant จะทำให้ compiler/interpreter แจ้ง error ทันทีถ้ามีใครพยายามเปลี่ยนมันโดยไม่ตั้งใจ

## เปรียบเทียบกับชีวิตจริง (Real-world analogy)

- **Variable** เหมือน **กล่องที่มีป้ายชื่อติดไว้** — กล่องชื่อ "เงินในกระเป๋า" ใส่เงินเข้าออกได้ตลอดเวลา ป้ายชื่อ (ชื่อตัวแปร) ไม่เปลี่ยน แต่ของข้างในเปลี่ยนได้
- **Data Type** เหมือน **ประเภทของภาชนะ** — แก้วน้ำใส่ของเหลวได้ (number), ตะกร้าใส่ผลไม้ได้หลายชิ้น (array/list), กล่องจดหมายใส่ได้แค่ true/false สองแบบ (boolean) — แต่ละภาชนะเหมาะกับของแต่ละประเภท เอาน้ำไปใส่ตะกร้าไม่ได้โดยตรง (ต้อง type conversion)
- **Constant** เหมือน **หมายเลขบัตรประชาชน** — กำหนดครั้งเดียวตอนเกิด แล้วห้ามเปลี่ยนตลอดชีวิต ต่างจากที่อยู่ (variable) ที่ย้ายบ้านได้เรื่อยๆ

## แผนภาพอธิบาย (Visual explanation)

### ตัวแปรกับหน่วยความจำ

```
โค้ด:  age = 25

ในหน่วยความจำ (Stack, จากบทที่ 3):
┌─────────────┬─────────┐
│  ชื่อตัวแปร   │  ค่า     │
├─────────────┼─────────┤
│    age      │   25    │  ← ตำแหน่งในหน่วยความจำ เช่น 0x001A
└─────────────┴─────────┘

โค้ด:  age = 26   (เปลี่ยนค่า)

┌─────────────┬─────────┐
│    age      │   26    │  ← ค่าเปลี่ยน แต่ตำแหน่ง/ชื่อเดิม
└─────────────┴─────────┘
```

### ชนิดข้อมูลพื้นฐาน (Primitive Data Types) — เปรียบเทียบข้ามภาษา

```
┌───────────────┬──────────────┬───────────────┬─────────────────┐
│  ชนิดข้อมูล     │  ตัวอย่างค่า   │  ขนาด (ทั่วไป)  │  ใช้เก็บอะไร      │
├───────────────┼──────────────┼───────────────┼─────────────────┤
│ Integer (int)  │  42, -7       │  4 ไบต์         │  จำนวนเต็ม        │
│ Float/Double   │  3.14, -0.5   │  4 หรือ 8 ไบต์   │  จำนวนทศนิยม      │
│ Boolean (bool) │  true, false  │  1 ไบต์         │  จริง/เท็จ        │
│ Character(char)│  'A', 'ก'     │  1-4 ไบต์       │  ตัวอักษรเดียว    │
│ String         │  "hello"      │  แปรผัน         │  ข้อความ (หลายตัวอักษร) │
└───────────────┴──────────────┴───────────────┴─────────────────┘
```

### Static Typing vs Dynamic Typing

```
Static Typing (เช่น Java, C++, Go, TypeScript)
   ─ ต้องประกาศชนิดข้อมูลชัดเจน ตรวจสอบตอน compile
       int age = 25;       // ถ้าเขียน age = "hi" ภายหลัง → error ตอน compile ทันที

Dynamic Typing (เช่น Python, JavaScript, Ruby)
   ─ ไม่ต้องประกาศชนิดข้อมูล ชนิดข้อมูลผูกกับ "ค่า" ไม่ใช่ "ตัวแปร" ตรวจตอนรันจริง
       age = 25             # ตอนนี้ age เป็น int
       age = "twenty-five"  # ตอนนี้ age กลายเป็น string ได้ — ไม่มี error ตอน compile
```

## ตัวอย่างโค้ด (Code example)

```python
# ===== Variables & Data Types =====
name = "Alice"          # str
age = 30                 # int
height = 1.65            # float
is_student = False       # bool

print(type(name))        # <class 'str'>
print(type(age))         # <class 'int'>

# ===== Type Conversion =====
age_text = str(age)              # int -> str: "30"
age_from_text = int("42")        # str -> int: 42
pi_int = int(3.99)               # float -> int: 3 (ตัดทศนิยมทิ้ง ไม่ปัดเศษ)

# ===== Constants =====
# Python ไม่มี keyword บังคับ constant จริงๆ ใช้ตัวพิมพ์ใหญ่ทั้งหมดเป็น "ข้อตกลง" (convention)
MAX_LOGIN_ATTEMPTS = 5
PI = 3.14159
```

```java
// ===== ภาษาที่เป็น static typing (Java) =====
int age = 30;                 // ต้องระบุชนิดข้อมูลชัดเจน
final double PI = 3.14159;    // "final" = constant จริงๆ ห้ามเปลี่ยนค่า
// PI = 3.14;                 // บรรทัดนี้จะ error ตอน compile ทันที ถ้าเปิดใช้งาน
```

## ทำงานทีละขั้นตอน (Step-by-step execution)

1. `name = "Alice"` — Python สร้าง string object `"Alice"` ใน Heap แล้วให้ชื่อตัวแปร `name` (บน Stack) ชี้ไปหามัน (ตามที่เรียนในบทที่ 3)
2. `type(name)` — Python (dynamic typing) ตรวจสอบชนิดข้อมูล**จากค่าที่เก็บอยู่จริง** ไม่ใช่จากการประกาศล่วงหน้า จึงตอบว่า `str`
3. `age_text = str(age)` — เกิด **type conversion** แบบชัดเจน (explicit conversion) แปลงตัวเลข 30 ให้กลายเป็นข้อความ `"30"` — คนละชนิดข้อมูลกันโดยสิ้นเชิง แม้จะดู "เหมือนกัน" เวลาพิมพ์ออกมา
4. ในตัวอย่าง Java: `final double PI = 3.14159;` — คอมไพเลอร์จะจดจำว่า `PI` เป็นค่าคงที่ ถ้ามีบรรทัดใดพยายามเขียนทับค่า `PI` ภายหลัง คอมไพเลอร์จะแจ้ง **error ทันทีตอน compile** (ก่อนโปรแกรมรันเสียอีก) ต่างจาก Python ที่ไม่มีการบังคับระดับภาษา

## Time Complexity

การอ่าน/เขียนค่าตัวแปรพื้นฐาน (int, float, bool) เป็น **O(1)** เสมอ เพราะเป็นการเข้าถึงตำแหน่งหน่วยความจำที่แน่นอนโดยตรง (ไม่ต้องค้นหา) ส่วนการแปลงชนิดข้อมูล (type conversion) ของค่าพื้นฐานก็เป็น O(1) เช่นกัน แต่การแปลงข้อความยาวๆ (เช่น string → list ของตัวอักษร) อาจเป็น O(n) ตามความยาวข้อความ

## Space Complexity

แต่ละชนิดข้อมูลใช้พื้นที่ต่างกัน (ตามตารางด้านบน) — การเลือกชนิดข้อมูลที่เหมาะสม (เช่น ใช้ `int32` แทน `int64` เมื่อค่าตัวเลขไม่มีทางเกินขอบเขต) มีผลโดยตรงต่อปริมาณหน่วยความจำที่โปรแกรมใช้ โดยเฉพาะเมื่อมีตัวแปรแบบนั้นจำนวนมาก (เช่น array ขนาดล้านตัว)

## แนวทางปฏิบัติที่ดี (Best Practices)

- ตั้งชื่อตัวแปรให้สื่อความหมาย (`userAge` ดีกว่า `x`) เพราะโค้ดถูกอ่านโดยมนุษย์บ่อยกว่าที่ถูกเขียน
- ใช้ constant สำหรับค่าที่ไม่ควรเปลี่ยน (magic number/string) แทนการเขียนตัวเลข/ข้อความตรงๆ กระจายอยู่ในโค้ดหลายจุด
- ในภาษา dynamic typing (Python, JS) ควรระวังการเปลี่ยนชนิดข้อมูลของตัวแปรเดิมกลางทาง เพราะทำให้โค้ดอ่านยากและเกิดบั๊กง่าย แม้ภาษาจะไม่ห้าม
- เลือกชนิดข้อมูลที่พอดีกับขอบเขตค่าที่ใช้จริง ไม่ใหญ่เกินความจำเป็น (มีผลกับ Space Complexity ข้างต้น)

## ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

- สับสนระหว่าง `=` (assignment, กำหนดค่า) กับ `==` (comparison, เปรียบเทียบค่า) — เป็นข้อผิดพลาดที่พบบ่อยที่สุดของมือใหม่ในหลายภาษา
- พยายามนำค่าคนละชนิดข้อมูลมาคำนวณกันโดยตรงโดยไม่แปลงชนิดก่อน (เช่น `"5" + 5` ในบางภาษาจะ error หรือได้ผลลัพธ์ไม่คาดคิด)
- ใช้ float แทนที่ควรใช้ integer สำหรับค่าที่ต้องแม่นยำ 100% เช่น เงิน (float มีปัญหาความคลาดเคลื่อนจากการเก็บเลขฐาน 2 เช่น `0.1 + 0.2 != 0.3` พอดีในหลายภาษา)
- คิดว่า constant ใน Python (ตัวพิมพ์ใหญ่) จะป้องกันการเปลี่ยนค่าจริงๆ — ที่จริงเป็นแค่ "ข้อตกลง" (convention) ไม่มีกลไกบังคับระดับภาษา

2. ทำไมการใช้ float เก็บค่าเงินถึงเป็นความคิดที่ไม่ดี? ควรใช้อะไรแทน?
3. Type conversion แบบ implicit กับ explicit ต่างกันอย่างไร ยกตัวอย่างแต่ละแบบ
4. ทำไมค่าคงที่ (constant) ถึงสำคัญในโค้ดคุณภาพดี?
5. `0.1 + 0.2 == 0.3` ในหลายภาษาให้ผลลัพธ์เป็น `False` เพราะอะไร?

## แบบฝึกหัด (Practice Exercises)

1. เขียนโปรแกรมประกาศตัวแปร 5 ชนิดข้อมูลที่ต่างกัน แล้วพิมพ์ทั้งค่าและชนิดข้อมูลของแต่ละตัว
2. ทดลองรันโค้ด `print(0.1 + 0.2)` ในภาษาที่ถนัด สังเกตผลลัพธ์ แล้วอธิบายว่าทำไมถึงไม่ได้ `0.3` พอดี (เชื่อมโยงกับเรื่องไบนารีจากบทที่ 2)
3. เขียนฟังก์ชันที่รับ string ที่เป็นตัวเลข (เช่น `"123"`) แปลงเป็น int แล้วบวกเพิ่ม 1 แล้วแปลงกลับเป็น string คืนค่าออกมา

**"Type Converter Tool"**: เขียนโปรแกรม command-line ที่:
1. รับ input จากผู้ใช้เป็นข้อความ
2. ตรวจสอบและแสดงผลว่า input นั้นสามารถแปลงเป็น int, float, หรือ bool ได้หรือไม่ (พร้อมค่าที่แปลงได้ถ้าทำได้)
3. เพิ่มฟีเจอร์คำนวณดอกเบี้ยง่ายๆ โดยใช้ constant สำหรับอัตราดอกเบี้ย และเปรียบเทียบผลลัพธ์เมื่อใช้ float กับเมื่อใช้ integer (หน่วยสตางค์) ในการคำนวณเงิน เพื่อสาธิตปัญหาความคลาดเคลื่อนของ float

## ข้อคิดสำคัญ (Key Takeaways)

- ตัวแปรคือชื่อที่ผูกกับตำแหน่งข้อมูลในหน่วยความจำ ทำให้โค้ดอ่านเข้าใจง่ายกว่าการอ้าง address ตรงๆ
- ชนิดข้อมูลกำหนดทั้งขนาดหน่วยความจำที่ใช้ และ operation ที่ทำได้กับค่านั้น
- Static typing ตรวจสอบชนิดข้อมูลตอน compile (ปลอดภัยกว่า, error เร็ว) ส่วน Dynamic typing ตรวจตอนรันจริง (ยืดหยุ่นกว่า, error ช้ากว่า)
- Constant มีไว้ล็อกค่าที่ไม่ควรเปลี่ยน ช่วยป้องกันบั๊กและสื่อเจตนาของโค้ด
- float มีปัญหาความคลาดเคลื่อนโดยธรรมชาติจากการเก็บเลขฐาน 2 — ไม่ควรใช้กับค่าที่ต้องแม่นยำ 100% เช่นเงิน
- บทถัดไปจะต่อยอดเรื่อง operators และ expressions ที่ใช้ตัวแปรและชนิดข้อมูลเหล่านี้มาคำนวณ
