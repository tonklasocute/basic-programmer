# บทที่ 1: คอมพิวเตอร์ทำงานอย่างไร (สรุปภาษาไทย)

> ไฟล์เนื้อหาเต็ม (ภาษาอังกฤษ): [01-how-computers-work.md](01-how-computers-work.md)

## แนวคิดหลัก

คอมพิวเตอร์เป็นเครื่องที่ "โง่แต่เร็วมาก" — ทำได้แค่คำสั่งพื้นฐาน (บวก, เปรียบเทียบ, ย้ายข้อมูล) แต่ทำได้เป็นพันล้านครั้งต่อวินาที คอมพิวเตอร์ประกอบด้วย 3 ส่วนหลักที่ทำงานร่วมกัน โดยมีความเร็วและขนาดต่างกันมาก:

- **CPU (หน่วยประมวลผล)** — "สมอง" คิดคำนวณและประมวลผลคำสั่งทีละขั้นตอน วนซ้ำ 4 ขั้น: **Fetch** (ดึงคำสั่ง) → **Decode** (แปลความหมาย) → **Execute** (ทำงาน) → **Writeback** (บันทึกผลลัพธ์) เร็วที่สุดแต่เก็บข้อมูลได้น้อยที่สุด (วัดเป็นนาโนวินาที)
- **RAM (หน่วยความจำหลัก)** — "ความจำระยะสั้น" เก็บข้อมูลและคำสั่งขณะโปรแกรมกำลังทำงาน เร็ว แต่ข้อมูลหายทันทีเมื่อปิดเครื่อง (volatile)
- **Disk (SSD/HDD)** — "ความจำระยะยาว" เก็บไฟล์ถาวร ช้ากว่า RAM มาก (หลายพันถึงหลายแสนเท่า) แต่ข้อมูลไม่หายแม้ปิดเครื่อง

## ทำไมต้องรู้เรื่องนี้

ภาษาโปรแกรมและเฟรมเวิร์กทั้งหมดมีไว้เพื่อให้มนุษย์สั่งงาน CPU ได้ง่ายขึ้น โดยไม่ต้องพูดภาษาเครื่อง (binary) ตรงๆ การเข้าใจฮาร์ดแวร์เบื้องหลังสำคัญเพราะ:

1. **ประสิทธิภาพ** — เข้าใจว่าทำไมโค้ดบางแบบเร็วกว่ากัน เพราะ RAM ช้ากว่า CPU cache ~100 เท่า และ Disk ช้ากว่า RAM ~100,000 เท่า
2. **การดีบัก** — คำว่า "out of memory", "stack overflow" จะเข้าใจได้จากโมเดลนี้
3. ทุก abstraction ระดับสูง (ตัวแปร, ฟังก์ชัน, object) สุดท้ายก็คือข้อมูลที่วิ่งไปมาระหว่าง CPU register, RAM, และ Disk

## เปรียบเทียบกับชีวิตจริง

เหมือนเชฟในครัว:
- **CPU** = เชฟ — สับ ผัด ชิม ได้ทีละอย่าง (หรือหลายคนพร้อมกัน = multi-core)
- **RAM** = เคาน์เตอร์ครัว — เก็บวัตถุดิบที่กำลังใช้ หยิบได้ทันที แต่พื้นที่จำกัด
- **Disk** = ห้องเก็บของ/ตู้เย็นหลังครัว — เก็บทุกอย่างที่เหลือ แต่ต้องเดินไปหยิบ ช้ากว่ามาก
- **CPU Cache** = กระเป๋าเสื้อกันเปื้อนเชฟ — เล็กมาก แต่เก็บของที่ใช้บ่อยที่สุด 2-3 อย่าง ไม่ต้องเอื้อมไปเคาน์เตอร์ด้วยซ้ำ

## ลำดับความเร็ว (จากเร็วสุดไปช้าสุด)

```
CPU Register        ~1 นาโนวินาที      (เร็วสุด เล็กสุด)
CPU Cache (L1-L3)   ~1-10 นาโนวินาที
RAM                 ~100 นาโนวินาที
SSD                 ~100,000 นาโนวินาที (0.1 มิลลิวินาที)
HDD                 ~10,000,000 นาโนวินาที (10 มิลลิวินาที)
เครือข่าย (Network)  ~100,000,000 นาโนวินาที (100 มิลลิวินาที)
```

ถ้าเทียบเป็นสเกลมนุษย์ (สมมติ register = 1 วินาที): RAM ≈ 2 นาที, SSD ≈ 1 วัน, HDD ≈ 4 เดือน, เครือข่าย ≈ 3 ปี

นี่คือเหตุผลว่าทำไม **caching, indexing, การลด disk/network access** ถึงสำคัญกว่าการ optimize คำสั่ง CPU เล็กๆ น้อยๆ

## บทเรียนจากตัวอย่างโค้ด

การวน loop อ่านข้อมูลแบบ **เรียงลำดับ (sequential)** จะเร็วกว่าการอ่านแบบ **สุ่ม (random)** ทั้งที่จำนวนการทำงานเท่ากันทุกประการ เพราะ CPU cache จะดึงข้อมูลที่อยู่ติดกันเข้ามาพร้อมกันเป็นก้อน (cache line) ทำให้การเข้าถึงข้อมูลที่อยู่ใกล้กันในหน่วยความจำเร็วกว่าการกระโดดไปมาแบบสุ่ม

## ข้อคิดสำคัญ (Key Takeaways)

- คอมพิวเตอร์ = CPU (คำนวณ) + RAM (ความจำเร็ว ชั่วคราว) + Disk (ความจำช้า ถาวร) เชื่อมกันด้วย bus
- ความเร็วต่างกันเป็นหลักสิบถึงหลักแสนเท่าในแต่ละชั้น
- CPU ทำงานวนซ้ำ fetch → decode → execute → writeback ตลอดเวลา
- ลำดับชั้นความเร็วนี้คือรากฐานของเทคนิค caching, indexing และการ optimize ประสิทธิภาพเกือบทั้งหมดที่จะเรียนต่อไป
- ทุก concept ระดับสูงในภาษาโปรแกรม สุดท้ายก็ถูก implement ผ่านการย้ายข้อมูลใน hierarchy นี้ทั้งสิ้น
