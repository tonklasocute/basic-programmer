# บทที่ 16: Trees, Binary Tree, BST, AVL Tree

## แนวคิดหลัก (Concept)

Hash Table (บทที่ 15) ค้นหาเร็วมากแต่**ไม่รักษาลำดับ** ส่วน Array/Linked List รักษาลำดับแต่ค้นหาช้า **Tree (ต้นไม้)** คือโครงสร้างข้อมูลที่จัดข้อมูลแบบ**ลำดับชั้น (hierarchy)** ทำให้ได้ทั้งความเร็วในการค้นหาและการรักษาลำดับ/ความสัมพันธ์แบบพ่อ-ลูกไปพร้อมกัน

- **Tree (ต้นไม้)** — โครงสร้างข้อมูลที่ประกอบด้วย **Node** เชื่อมกันแบบลำดับชั้น มี **Root (ราก)** เป็น Node บนสุด และแต่ละ Node มี **Child (ลูก)** ได้หลายตัว แต่มี **Parent (พ่อแม่)** ได้แค่ 1 ตัวเท่านั้น (ต่างจาก Graph ที่จะเรียนภายหลัง ซึ่งไม่มีข้อจำกัดนี้)
- **Binary Tree (ต้นไม้ทวิภาค)** — Tree ที่แต่ละ Node มีลูกได้**สูงสุด 2 ตัว** เรียกว่า **left child** และ **right child**
- **BST (Binary Search Tree)** — Binary Tree ที่มีกฎเพิ่มเติม: **ทุก Node ทางซ้ายมีค่าน้อยกว่า Node นั้น และทุก Node ทางขวามีค่ามากกว่า** กฎนี้ทำให้ค้นหาข้อมูลได้เร็วแบบเดียวกับ Binary Search (จะเรียนในบทที่ 22)
- **AVL Tree** — BST ที่ **สมดุลตัวเองอัตโนมัติ (self-balancing)** เพื่อป้องกันปัญหา BST ที่เอียงจนกลายเป็นเหมือน Linked List (จะอธิบายด้านล่าง)

## ทำไมต้องมีสิ่งนี้ (Why it exists)

- **Tree มีไว้จัดข้อมูลที่มีธรรมชาติเป็นลำดับชั้นอยู่แล้ว**: ระบบไฟล์ (โฟลเดอร์ในโฟลเดอร์), โครงสร้างองค์กร (หัวหน้า-ลูกน้อง), โครงสร้าง HTML/DOM (element ซ้อน element) ล้วนเป็นลำดับชั้นโดยธรรมชาติ — Array/Linked List แบบเรียงเส้นตรงไม่เหมาะกับข้อมูลแบบนี้
- **BST มีไว้ให้ค้นหาเร็วโดยยังรักษาลำดับได้**: กฎ "ซ้ายน้อยกว่า ขวามากกว่า" ทำให้ทุกครั้งที่เทียบค่าที่ Node หนึ่ง เราสามารถ**ตัดข้อมูลทิ้งครึ่งหนึ่งทันที** (ถ้าค่าที่หาน้อยกว่า Node ปัจจุบัน ไม่ต้องดูฝั่งขวาเลย) หลักการเดียวกับ Binary Search บน Array ที่เรียงแล้ว
- **AVL Tree มีไว้แก้ปัญหา BST ที่ "เอียง" จนเสียคุณสมบัติความเร็ว**: ถ้าใส่ข้อมูลที่เรียงลำดับอยู่แล้ว (เช่น 1,2,3,4,5) เข้า BST ธรรมดาไปเรื่อยๆ มันจะกลายเป็นเส้นตรงเอียงไปทางเดียว (เหมือน Linked List) ทำให้เสียข้อได้เปรียบด้าน O(log n) ไปเลย AVL Tree แก้ปัญหานี้ด้วยการ **หมุนโครงสร้าง (rotation)** โดยอัตโนมัติทุกครั้งที่เสียสมดุล

## เปรียบเทียบกับชีวิตจริง (Real-world analogy)

- **Tree** เหมือน **แผนผังองค์กรบริษัท** — CEO (root) มีรองประธานหลายคน (children) แต่ละรองประธานมีผู้จัดการใต้บังคับบัญชา (grandchildren) พนักงานแต่ละคนมีหัวหน้าโดยตรงแค่คนเดียว (parent เดียว) แต่หัวหน้าคนหนึ่งดูแลลูกน้องได้หลายคน
- **BST** เหมือน **การเดาตัวเลขแบบ "สูงไป-ต่ำไป"** — ถ้าเลขที่เดาน้อยกว่าคำตอบ ไม่ต้องเสียเวลาดูฝั่งที่น้อยกว่าเดาอีกเลย ตัดข้อมูลทิ้งครึ่งหนึ่งได้ทันทีทุกครั้งที่เดา
- **AVL Tree (self-balancing)** เหมือน **ต้นไม้ในสวนที่มีคนตัดแต่งกิ่งสม่ำเสมอ** — ถ้าปล่อยให้กิ่งด้านหนึ่งยาวเอียงไปทางเดียวโดยไม่ตัดแต่ง ต้นไม้จะล้มในที่สุด (เสียสมดุล) ต้องมีคนคอยปรับสมดุลให้ทุกครั้งที่กิ่งเริ่มเอียงเกินไป

        ┌──────┴──────┐    ┌──────┴──────┐

### BST — กฎ "ซ้ายน้อยกว่า ขวามากกว่า"

```
                    ┌─────┐
                    │ 50  │
                    └──┬──┘
              ┌────────┴────────┐
           ┌──┴──┐            ┌──┴──┐
           │ 30  │            │ 70  │
           │(<50)│            │(>50)│
           └──┬──┘            └──┬──┘
        ┌──────┴──────┐    ┌──────┴──────┐
     ┌──┴──┐        ┌──┴──┐┌──┴──┐     ┌──┴──┐
     │ 20  │        │ 40  ││ 60  │     │ 80  │
     │(<30)│        │(>30)││(<70)│     │(>70)│
     └─────┘        └─────┘└─────┘     └─────┘

ค้นหา 60:  เริ่มที่ 50 -> 60>50 ไปขวา -> เจอ 70 -> 60<70 ไปซ้าย -> เจอ 60 ✓ (แค่ 3 ครั้งเทียบ จาก 7 ตัว)
```

### AVL Tree — การหมุน (Rotation) เพื่อรักษาสมดุล

```
ก่อนหมุน (เอียงขวา, unbalanced):        หลังหมุนซ้าย (Left Rotation):

10                                          20
  \                                        /  \
   20                    ────►           10    30
     \
      30

ผลลัพธ์: ความสูงของทั้งสองฝั่งสมดุลกันแล้ว -> รักษา O(log n) ไว้ได้เสมอ
```

## ตัวอย่างโค้ด (Code example)

```python
class TreeNode:
    def __init__(self, value):
        self.value = value
        self.left = None
        self.right = None

class BST:
    def __init__(self):
        self.root = None

    def insert(self, value):
        if self.root is None:
            self.root = TreeNode(value)
            return
        self._insert_recursive(self.root, value)

    def _insert_recursive(self, node, value):
        if value < node.value:
            if node.left is None:
                node.left = TreeNode(value)
            else:
                self._insert_recursive(node.left, value)     # recursion (บทที่ 9)
        else:
            if node.right is None:
                node.right = TreeNode(value)
            else:
                self._insert_recursive(node.right, value)

    def search(self, value):
        current = self.root
        while current is not None:
            if value == current.value:
                return True
            elif value < current.value:
                current = current.left      # ตัดฝั่งขวาทิ้งทั้งหมด
            else:
                current = current.right      # ตัดฝั่งซ้ายทิ้งทั้งหมด
        return False

    def inorder_traversal(self, node, result=None):    # ไล่แบบ ซ้าย-กลาง-ขวา
        if result is None:
            result = []
        if node is not None:
            self.inorder_traversal(node.left, result)
            result.append(node.value)
            self.inorder_traversal(node.right, result)
        return result

bst = BST()
for value in [50, 30, 70, 20, 40, 60, 80]:
    bst.insert(value)

print(bst.search(60))                  # True
print(bst.inorder_traversal(bst.root))  # [20, 30, 40, 50, 60, 70, 80] -> เรียงลำดับพอดี!
```

## ทำงานทีละขั้นตอน (Step-by-step execution)

1. `bst.insert(30)` (หลัง insert 50 ไปแล้ว) — เทียบ `30 < 50` (True) → ไปทางซ้าย → `node.left is None` (True) → สร้าง `TreeNode(30)` วางไว้ที่ `root.left`
2. `bst.search(60)` — เริ่มที่ root (50): `60 == 50`? ไม่ใช่ → `60 < 50`? ไม่ใช่ → ไปทาง `current.right` (70) → `60 == 70`? ไม่ใช่ → `60 < 70`? ใช่ → ไปทาง `current.left` (60) → `60 == 60` ✓ คืนค่า `True` — สังเกตว่าตัด Node ฝั่งซ้ายของ root (20, 30, 40) ทิ้งไปตั้งแต่ก้าวแรก โดยไม่ต้องแตะเลย
3. `bst.inorder_traversal(bst.root)` — เทคนิค **Inorder Traversal** (ไล่ซ้ายก่อน แล้วค่อยเก็บค่าตัวเอง แล้วค่อยไล่ขวา) ของ BST จะได้ผลลัพธ์ **เรียงลำดับจากน้อยไปมากเสมอ** เพราะกฎ "ซ้ายน้อยกว่า ขวามากกว่า" การันตีลำดับนี้ไว้ในโครงสร้างอยู่แล้ว — นี่คือคุณสมบัติพิเศษที่ Hash Table (บทที่ 15) ไม่มี

## Time Complexity

| Operation | Balanced BST/AVL | Unbalanced BST (กรณีแย่สุด) |
|---|---|---|
| ค้นหา (search) | O(log n) | O(n) |
| แทรก (insert) | O(log n) | O(n) |
| ลบ (delete) | O(log n) | O(n) |

**ทำไม O(log n)?** — เพราะทุกครั้งที่เทียบค่าที่ Node หนึ่ง เราตัดข้อมูลทิ้งได้ครึ่งหนึ่งเสมอ (เหมือน Binary Search) จำนวนครั้งที่ต้องเทียบเพื่อลดข้อมูลจาก n เหลือ 1 คือ log₂(n) ครั้ง — แต่สิ่งนี้เป็นจริง**ก็ต่อเมื่อต้นไม้สมดุล** (ตามภาพ "BST ที่เอียง" ด้านบน) นี่คือเหตุผลที่ AVL Tree จำเป็น: มันรับประกันว่าต้นไม้จะสมดุลเสมอ ทำให้ O(log n) เป็นจริงในทุกกรณี ไม่ใช่แค่กรณีที่โชคดี

## Space Complexity

Tree ใช้พื้นที่ **O(n)** ตามจำนวน Node เช่นเดียวกับโครงสร้างข้อมูลอื่น แต่การ recursive traversal (เช่น `inorder_traversal`) ใช้พื้นที่ **Stack เพิ่มเติม O(h)** โดย h คือความสูงของต้นไม้ (เชื่อมโยงกับ Call Stack จากบทที่ 3 และ Recursion จากบทที่ 9) — ถ้าต้นไม้สมดุล h = O(log n) แต่ถ้าเอียงสุดๆ h = O(n)

## ข้อดี (Advantages)

- BST/AVL: ค้นหา แทรก ลบ ได้เร็ว O(log n) พร้อมทั้งรักษาลำดับข้อมูลไว้ได้ (ต่างจาก Hash Table)
- Traversal แบบ inorder ให้ข้อมูลที่เรียงลำดับโดยอัตโนมัติ
- AVL รับประกันความสมดุลเสมอ ไม่มีทางเสื่อมสภาพเป็น O(n) เหมือน BST ธรรมดา

## ข้อเสีย (Disadvantages)

- BST ธรรมดาเสี่ยงเอียงจนกลายเป็น O(n) ถ้าใส่ข้อมูลที่เรียงลำดับอยู่แล้ว
- AVL Tree ต้องคำนวณและหมุนโครงสร้างทุกครั้งที่แทรก/ลบ ทำให้ operation แต่ละครั้งมี overhead มากกว่า BST ธรรมดาเล็กน้อย (แต่แลกมากับการรับประกัน O(log n) เสมอ)
- ค้นหาช้ากว่า Hash Table (O(log n) เทียบกับ O(1)) ถ้าไม่สนใจเรื่องลำดับข้อมูลเลย

## การใช้งานจริง (Real-world usage)

- ระบบไฟล์ (File System) และโครงสร้าง DOM ของหน้าเว็บเป็น Tree โดยธรรมชาติ
- Database Index (B-Tree/B+ Tree ซึ่งเป็นญาติของ BST) ใช้ค้นหาแถวข้อมูลในตารางขนาดใหญ่อย่างรวดเร็ว
- Autocomplete/Dictionary lookup ที่ต้องการข้อมูลเรียงลำดับ (แม้ Trie ในบทถัดไปจะเหมาะกับงานนี้มากกว่าเฉพาะทาง)
- โครงสร้างการตัดสินใจ เช่น Decision Tree ในงาน Machine Learning

## แนวทางปฏิบัติที่ดี (Best Practices)

- ถ้าข้อมูลที่จะใส่อาจเรียงลำดับอยู่แล้ว (หรือใกล้เคียง) ควรใช้ **Self-Balancing Tree (AVL หรือ Red-Black Tree)** แทน BST ธรรมดาเสมอ เพื่อป้องกันปัญหาเอียง
- ถ้าไม่สนใจเรื่องลำดับข้อมูลเลย และต้องการแค่ค้นหาเร็วที่สุด ให้กลับไปใช้ Hash Table (บทที่ 15) แทน เพราะ O(1) เร็วกว่า O(log n)
- ใช้ inorder traversal เมื่อต้องการดึงข้อมูลออกมาเป็นลำดับที่เรียงแล้ว

## ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

- ใช้ BST ธรรมดากับข้อมูลที่เรียงลำดับอยู่แล้ว (เช่น timestamp ที่เพิ่มขึ้นเรื่อยๆ) โดยไม่รู้ตัวว่าจะกลายเป็น O(n) แทนที่จะเป็น O(log n)
- สับสนระหว่าง Binary Tree (แค่มีลูกไม่เกิน 2) กับ BST (มีกฎ "ซ้ายน้อยกว่า ขวามากกว่า" เพิ่มเข้ามา) — ไม่ใช่ Binary Tree ทุกต้นจะเป็น BST
- ลืมจัดการกรณีลบ Node ที่มีลูกทั้งสองข้าง (ต้องหาตัวแทนที่เหมาะสม เช่น ค่าน้อยที่สุดของฝั่งขวา) ทำให้โครงสร้าง BST เสียหายหลังลบ
- เขียน recursive traversal บนต้นไม้ที่ลึกมากโดยไม่ระวัง อาจเกิด Stack Overflow (เชื่อมโยงกับบทที่ 3 และ 9)

**"ระบบจัดการรายชื่อผู้ติดต่อแบบเรียงลำดับ (Sorted Contact Book)"**: เขียนโปรแกรมที่:
1. ใช้ BST เก็บรายชื่อผู้ติดต่อ (เรียงตามชื่อ) รองรับคำสั่งเพิ่ม/ค้นหา/แสดงรายชื่อทั้งหมดแบบเรียงลำดับ (ใช้ inorder traversal)
2. เปรียบเทียบความสูงของ BST เมื่อใส่ชื่อแบบสุ่ม เทียบกับใส่ชื่อที่เรียงตามตัวอักษรอยู่แล้ว (A, B, C, D, ...) แสดงให้เห็นปัญหาการเอียง
3. (ท้าทายเพิ่มเติม) implement การหมุน (rotation) พื้นฐานของ AVL Tree แล้ววัดว่าความสูงคงที่ใกล้เคียง log(n) แม้ใส่ข้อมูลเรียงลำดับหรือไม่

## ข้อคิดสำคัญ (Key Takeaways)

- Tree จัดข้อมูลแบบลำดับชั้น เหมาะกับข้อมูลที่มีความสัมพันธ์แบบพ่อ-ลูกโดยธรรมชาติ
- BST มีกฎ "ซ้ายน้อยกว่า ขวามากกว่า" ทำให้ค้นหา/แทรก/ลบเร็ว O(log n) โดยตัดข้อมูลทิ้งครึ่งหนึ่งทุกครั้งที่เทียบ
- BST ธรรมดาเสี่ยงเอียงจนกลายเป็น O(n) ถ้าข้อมูลเข้ามาแบบเรียงลำดับ — AVL Tree แก้ปัญหานี้ด้วยการหมุนโครงสร้างอัตโนมัติเพื่อรักษาสมดุลเสมอ
- Inorder traversal บน BST ให้ผลลัพธ์เรียงลำดับเสมอ ซึ่งเป็นข้อได้เปรียบที่ Hash Table ไม่มี
- เลือก BST/AVL เมื่อต้องการทั้งความเร็วและลำดับข้อมูล เลือก Hash Table เมื่อสนใจแค่ความเร็วในการค้นหาอย่างเดียว
- บทถัดไปจะเรียน Heap & Priority Queue ซึ่งเป็น Tree อีกแบบที่มีกฎต่างออกไป ใช้แก้ปัญหา "หาค่าสูงสุด/ต่ำสุดเร็วที่สุด" โดยเฉพาะ
