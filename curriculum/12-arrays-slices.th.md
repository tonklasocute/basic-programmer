# บทที่ 12: Arrays & Slices //ต้องดู

## แนวคิดหลัก (Concept)

ตั้งแต่บทที่ 5 เราเก็บค่าทีละตัวในตัวแปรเดียว แต่ในโลกจริงเราต้องเก็บ**ชุดของข้อมูล**จำนวนมาก (รายชื่อนักเรียน 50 คน, คะแนนสอบ 1,000 ข้อ) — **Array (อาร์เรย์)** คือโครงสร้างข้อมูลแรกที่แก้ปัญหานี้

- **Array (อาร์เรย์)** — โครงสร้างข้อมูลที่เก็บสมาชิกหลายตัว **เรียงต่อกันในหน่วยความจำ (Heap) แบบติดกันเป็นแถวเดียว (contiguous memory)** เข้าถึงสมาชิกแต่ละตัวผ่าน **index** (ตำแหน่ง เริ่มนับจาก 0)
- **Static Array (อาร์เรย์ขนาดคงที่)** — ต้องกำหนดขนาดตายตัวตอนสร้าง (พบใน C, Java เป็นต้น) เปลี่ยนขนาดภายหลังไม่ได้
- **Dynamic Array / List (อาร์เรย์ขนาดไม่คงที่)** — ขยาย/หดขนาดได้อัตโนมัติ (พบใน Python `list`, JavaScript `Array`, Java `ArrayList`) — เบื้องหลังยังคงใช้ contiguous memory เหมือนเดิม แต่มีกลไกจัดการขยายขนาดให้อัตโนมัติ
- **Slice (สไลซ์)** — วิธี "หยิบบางส่วน" ของอาร์เรย์ออกมาโดยระบุช่วง index เช่น `arr[2:5]`

## ทำไมต้องมีสิ่งนี้ (Why it exists)

- **Array มีไว้แก้ปัญหาการเก็บข้อมูลจำนวนมากอย่างมีระเบียบ**: ถ้าต้องเก็บคะแนน 1,000 คน การสร้างตัวแปร `score1, score2, ..., score1000` เป็นไปไม่ได้จริง Array ให้เก็บทั้งหมดในตัวแปรเดียวและเข้าถึงด้วย index
- **การเก็บข้อมูลติดกันในหน่วยความจำ (contiguous) มีไว้เพื่อความเร็ว**: เพราะ CPU รู้ตำแหน่งเริ่มต้นของอาร์เรย์และขนาดของแต่ละสมาชิก จึงคำนวณตำแหน่งของสมาชิกตัวที่ i ได้ทันทีด้วยสูตรคณิตศาสตร์ (`start_address + i * element_size`) โดยไม่ต้องไล่ค้นหาทีละตัว — นี่ทำให้การเข้าถึง array ผ่าน index เป็น **O(1)** เสมอ (เชื่อมโยงกับเรื่อง cache-friendly sequential access จากบทที่ 1)
- **Slice มีไว้ทำงานกับข้อมูลบางส่วนโดยไม่ต้องเขียน loop คัดลอกเอง**: การหยิบ "5 รายการแรก" หรือ "รายการที่ 3 ถึง 7" เป็นงานที่พบบ่อยมาก Slice ให้ทำสิ่งนี้ได้ในบรรทัดเดียวแทนที่จะเขียน loop ทุกครั้ง

## เปรียบเทียบกับชีวิตจริง (Real-world analogy)

- **Array** เหมือน **ตู้ล็อกเกอร์แถวเดียวที่มีเลขกำกับ** — ล็อกเกอร์หมายเลข 0, 1, 2, 3, ... เรียงติดกัน รู้เลขล็อกเกอร์ก็เดินตรงไปเปิดได้ทันทีโดยไม่ต้องเดินผ่านล็อกเกอร์อื่นก่อน (ต่างจากการเดินหาของทีละจุดในบ้านที่ไม่มีระบบเลข)
- **Static vs Dynamic Array** เหมือน **ตู้ล็อกเกอร์ที่จำนวนช่องตายตัว (static)** เทียบกับ **ตู้ล็อกเกอร์ที่เรียกช่างมาต่อเติมเพิ่มช่องให้เมื่อเต็ม (dynamic)** — การต่อเติมใช้เวลาและทรัพยากรเพิ่ม แต่สะดวกกว่าไม่ต้องรู้จำนวนล่วงหน้า
- **Slice** เหมือน **การขอถ่ายเอกสารเฉพาะหน้า 3-7 ของหนังสือทั้งเล่ม** — ไม่ต้องคัดลอกทั้งเล่ม แค่ระบุช่วงหน้าที่ต้องการ

## แผนภาพอธิบาย (Visual explanation)

### โครงสร้าง Array ในหน่วยความจำ

```
Array:        [10, 20, 30, 40, 50]
Index:          0   1   2   3   4

หน่วยความจำ (Heap) — เก็บติดกันเป็นแถวเดียว, สมมติแต่ละช่องใช้ 4 ไบต์:

Address:   0x100   0x104   0x108   0x10C   0x110
Value:      10      20      30      40      50
             ▲
        arr[0] อยู่ที่ 0x100 (จุดเริ่มต้น)

ต้องการ arr[3]:
  address = start_address + (3 * 4 ไบต์) = 0x100 + 12 = 0x10C
  -> เข้าถึงได้ทันที ไม่ต้องไล่นับจาก arr[0] -> arr[1] -> arr[2] -> arr[3]
  -> นี่คือเหตุผลที่ array access เป็น O(1)
```

### การแทรก/ลบสมาชิกในอาร์เรย์ — ทำไมช้า (O(n))

```
Array เดิม:  [10, 20, 30, 40, 50]

แทรก 99 ที่ index 1:
  ต้อง "เลื่อน" สมาชิกทุกตัวตั้งแต่ index 1 เป็นต้นไปไปทางขวาก่อน:

  [10, _ , 20, 30, 40, 50]     <- เลื่อน 20,30,40,50 ไปทางขวาทั้งหมด
  [10, 99, 20, 30, 40, 50]     <- ค่อยใส่ 99 ลงช่องที่ว่าง

  worst case: แทรกที่ index 0 -> เลื่อนสมาชิกทั้งหมด n ตัว -> O(n)
```

### Slice — หยิบบางส่วนของ Array

```python
arr = [10, 20, 30, 40, 50]
#       0   1   2   3   4

arr[1:4]     # index 1 ถึง 3 (ไม่รวม index 4) -> [20, 30, 40]
arr[:3]      # ตั้งแต่ต้นถึง index 2           -> [10, 20, 30]
arr[2:]      # ตั้งแต่ index 2 ถึงท้าย           -> [30, 40, 50]
arr[::-1]    # กลับด้าน (reverse)               -> [50, 40, 30, 20, 10]
```

### Dynamic Array — การขยายขนาดเบื้องหลัง (Amortized Growth)

```
Python list เริ่มจอง capacity ไว้เกินกว่าที่ใช้จริงเล็กน้อยเสมอ
เมื่อเต็ม -> จองพื้นที่ใหม่ขนาดใหญ่กว่าเดิม (มักเป็น 1.5x - 2x) -> copy ข้อมูลเก่าทั้งหมดไปที่ใหม่

capacity=4: [1,2,3,4]           ใช้เต็ม 4/4
append(5)  -> จองใหม่ขนาด 8: [1,2,3,4,5,_,_,_]   <- copy ข้อมูลเดิมทั้งหมด (ครั้งนี้ช้า O(n))
append(6)  -> ใส่ในช่องว่างที่เหลือ: [1,2,3,4,5,6,_,_]  <- เร็ว O(1) เพราะยังมีที่ว่าง
```

## ตัวอย่างโค้ด (Code example)

```python
# ===== สร้างและเข้าถึง Array (list ใน Python) =====
scores = [85, 90, 78, 92, 88]
print(scores[0])         # 85  -> O(1) เข้าถึงทันที
print(scores[-1])         # 88  -> index ติดลบ = นับจากท้าย

# ===== แก้ไขค่า =====
scores[2] = 80            # O(1)

# ===== เพิ่ม/ลบสมาชิก =====
scores.append(95)         # O(1) โดยเฉลี่ย (amortized) - เพิ่มท้าย list
scores.insert(0, 100)     # O(n) - ต้องเลื่อนสมาชิกทั้งหมดไปทางขวา
scores.pop()               # O(1) - ลบตัวสุดท้าย
scores.pop(0)               # O(n) - ลบตัวแรก ต้องเลื่อนสมาชิกที่เหลือมาชิดซ้าย

# ===== Slice =====
top_three = scores[:3]     # หยิบ 3 ตัวแรก -> สร้าง list ใหม่ (copy) ไม่กระทบต้นฉบับ
reversed_scores = scores[::-1]

# ===== วน loop ประมวลผล array (เชื่อมโยงกับบทที่ 11) =====
total = 0
for score in scores:
    total += score
average = total / len(scores)
```

## ทำงานทีละขั้นตอน (Step-by-step execution)

1. `scores[0]` — Python คำนวณตำแหน่งหน่วยความจำของสมาชิกตัวที่ 0 โดยตรงจากที่อยู่เริ่มต้นของ list บวกกับ offset (`0 * ขนาดต่อสมาชิก`) แล้วอ่านค่าจาก RAM ทันที — ไม่ต้องไล่ผ่านสมาชิกตัวอื่นเลย จึงเป็น **O(1)**
2. `scores.insert(0, 100)` — Python ต้อง**เลื่อนสมาชิกทุกตัวที่มีอยู่เดิม**ไปทางขวาหนึ่งตำแหน่งก่อน (เพื่อเปิดช่องว่างที่ index 0) แล้วจึงใส่ค่า 100 ลงไป จำนวนการเลื่อนเท่ากับจำนวนสมาชิกทั้งหมด จึงเป็น **O(n)**
3. `scores.append(95)` — ถ้า list ยังมีพื้นที่ว่างเหลือ (capacity มากกว่า length) จะใส่ค่าใหม่ต่อท้ายทันที O(1) แต่ถ้าพื้นที่เต็มพอดี Python จะขยาย capacity โดยจองพื้นที่ใหม่ที่ใหญ่กว่า (มักเป็น ~1.125x-2x) แล้ว copy ข้อมูลเดิมทั้งหมดไปที่ใหม่ (รอบนั้นเป็น O(n)) — แต่เพราะการขยายไม่ได้เกิดขึ้นทุกครั้ง เมื่อเฉลี่ยจากการเรียกจำนวนมากๆ (amortized) จึงถือว่า O(1) โดยเฉลี่ย
4. `top_three = scores[:3]` — Slice ใน Python สร้าง **list ใหม่** ที่คัดลอกค่าจากช่วงที่ระบุ ไม่ใช่แค่ "มองไปที่" ข้อมูลเดิม (ต่างจากภาษาอื่นบางภาษา เช่น Go ที่ slice แชร์หน่วยความจำเดิม) ดังนั้นการแก้ไข `top_three` จะไม่กระทบ `scores` ต้นฉบับ

## Time Complexity

| Operation | Complexity | เหตุผล |
|---|---|---|
| เข้าถึงด้วย index (`arr[i]`) | O(1) | คำนวณตำแหน่งได้ตรงจากสูตรคณิตศาสตร์ |
| ค้นหาค่า (ไม่รู้ index) | O(n) | ต้องไล่ตรวจทีละตัวจนกว่าจะเจอ |
| เพิ่ม/ลบที่ท้าย (append/pop) | O(1) โดยเฉลี่ย | มีพื้นที่ว่างเผื่อไว้ ไม่ต้องเลื่อนสมาชิก |
| เพิ่ม/ลบที่ต้นหรือกลาง (insert/pop ที่ index อื่น) | O(n) | ต้องเลื่อนสมาชิกที่เหลือทั้งหมด |
| Slice `arr[a:b]` | O(k) โดย k คือขนาดของช่วงที่หยิบ | ต้องคัดลอกข้อมูล k ตัว |

## Space Complexity

Array พื้นฐานใช้พื้นที่ **O(n)** ตามจำนวนสมาชิก — Dynamic Array อาจใช้พื้นที่มากกว่า n เล็กน้อยเสมอ (เผื่อ capacity สำหรับการขยายในอนาคต) ซึ่งเป็นการแลกเปลี่ยน (trade-off) ระหว่างพื้นที่ที่เสียเปล่าบางส่วนกับความเร็วของการ append โดยเฉลี่ย

## ข้อดี (Advantages)

- เข้าถึงสมาชิกด้วย index ได้เร็วมาก O(1)
- ใช้หน่วยความจำอย่างมีประสิทธิภาพ (ไม่มี overhead ต่อสมาชิกเหมือนโครงสร้างข้อมูลอื่น เช่น Linked List ที่ต้องเก็บ pointer เพิ่ม)
- Cache-friendly เพราะข้อมูลอยู่ติดกันในหน่วยความจำ (ตามหลักการบทที่ 1)

## ข้อเสีย (Disadvantages)

- แทรก/ลบสมาชิกที่ต้นหรือกลาง array มีค่าใช้จ่ายสูง O(n)
- Static array ต้องรู้ขนาดล่วงหน้า เปลี่ยนขนาดภายหลังไม่ได้ (ในภาษาที่มี static array แท้จริงเช่น C)
- การขยายขนาดของ Dynamic array บางครั้งต้อง copy ข้อมูลทั้งหมด ทำให้บางรอบช้ากว่าปกติ

## การใช้งานจริง (Real-world usage)

- เก็บรายการข้อมูลที่ต้องเข้าถึงแบบสุ่มบ่อยๆ ผ่าน index (เช่น ตารางคะแนน, pixel ของรูปภาพ)
- เป็นโครงสร้างพื้นฐานที่ใช้สร้างโครงสร้างข้อมูลอื่นต่อ (Stack, Queue, Hash Table มักใช้ array เป็นพื้นฐานภายใน)
- ใช้เก็บ matrix/ตาราง 2 มิติในงานคำนวณเชิงวิทยาศาสตร์ ภาพ และ machine learning

## แนวทางปฏิบัติที่ดี (Best Practices)

- ใช้ `append`/เพิ่มท้าย array แทนการ `insert` ที่ต้น/กลาง เมื่อสามารถออกแบบให้ทำได้ เพื่อประสิทธิภาพที่ดีกว่า
- ถ้าต้องแทรก/ลบสมาชิกที่ต้น/กลางบ่อยๆ ควรพิจารณาใช้โครงสร้างข้อมูลอื่น เช่น Linked List (บทถัดไป) แทน
- ใช้ slice แทนการเขียน loop คัดลอกข้อมูลเองเมื่อทำได้ เพื่อความกระชับและลดโอกาสเขียนผิด (off-by-one error)

## ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

- **Index out of range** — เข้าถึง index ที่ไม่มีอยู่จริง (เช่น `arr[10]` ทั้งที่ array มีแค่ 5 สมาชิก) ทำให้เกิด error
- **Off-by-one error** — สับสนว่า index เริ่มจาก 0 หรือ 1 หรือคำนวณขอบเขตของ slice ผิดไปหนึ่งตำแหน่ง
- เข้าใจผิดว่า `insert`/`pop` ที่ตำแหน่งใดก็ตามมีความเร็วเท่ากับที่ท้าย array (ลืมว่า O(n) เมื่อไม่ใช่ปลาย array)
- ในบางภาษา แก้ไข slice โดยเข้าใจผิดว่ากระทบต้นฉบับ (หรือกลับกัน) — ต้องรู้ว่าภาษาที่ใช้ทำ slice แบบ copy หรือแบบแชร์หน่วยความจำเดิม

2. รองรับคำสั่ง: เพิ่มนักเรียนใหม่ (append), ลบนักเรียนตามชื่อ (ค้นหาแล้วลบ — สังเกตว่าต้องค้นหาก่อน O(n)), แก้ไขคะแนน, และคำนวณค่าเฉลี่ย/สูงสุด/ต่ำสุดของทั้งชั้น

4. วัดเวลาการทำงานเปรียบเทียบระหว่างการลบนักเรียนที่อยู่ต้น list กับท้าย list เมื่อมีข้อมูลจำนวนมาก (เช่น 100,000 คน) เพื่อพิสูจน์ความแตกต่างของ O(n) กับ O(1)

## ข้อคิดสำคัญ (Key Takeaways)

- Array เก็บข้อมูลติดกันในหน่วยความจำ ทำให้เข้าถึงผ่าน index ได้เร็วมาก O(1) เพราะคำนวณตำแหน่งได้โดยตรง
- การแทรก/ลบที่ต้นหรือกลาง array มีค่าใช้จ่าย O(n) เพราะต้องเลื่อนสมาชิกที่เหลือ ส่วนที่ท้ายมักเป็น O(1) โดยเฉลี่ย
- Dynamic Array ขยายขนาดอัตโนมัติโดยจองพื้นที่เผื่อไว้ล่วงหน้า ทำให้ append เร็วโดยเฉลี่ยแม้บางรอบจะช้ากว่าปกติ (amortized O(1))
- Slice ใช้หยิบข้อมูลบางส่วนออกมาได้กระชับ แต่ต้องรู้ว่าภาษาที่ใช้ copy ข้อมูลหรือแชร์หน่วยความจำเดิม
- Array เป็นโครงสร้างข้อมูลพื้นฐานที่สุด และเป็นฐานสำคัญก่อนเรียนโครงสร้างข้อมูลที่ซับซ้อนขึ้นในบทถัดไป: Linked List ซึ่งแก้ปัญหาการแทรก/ลบที่ช้าของ Array ได้ (แลกกับข้อเสียอื่น)
